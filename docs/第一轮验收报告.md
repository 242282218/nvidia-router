# NVIDIA API 路由器第一轮最终验收报告

## 1. 验收结论

- **验收对象：** NVIDIA API 路由器第一轮 MVP。
- **验收基线：** `HEAD 3447bc4`（分支 `feat/nvidia-router-mvp`）。
- **验收日期：** 2026-07-31。
- **报告实施提交：** 本报告将以 `docs: 记录 NVIDIA 路由器第一轮验收结果` 提交。
- **最终结论：FAIL/BLOCKED。**

普通 Go 测试、前端静态检查/单元测试/构建、Mock NVIDIA 普通重复测试和 E2E 测试列举均有证据；但是第一轮发布门禁仍未通过。以下阻断项没有被折算为通过：

1. `go test -race ./...` 和 `go test -race ./tests/mocknvidia -count=10` 在当前 Windows 环境因 CGO/GCC 不可用而 BLOCKED。
2. `bash tests/e2e/run.sh` 和 `bash scripts/check-secrets.sh` 在当前环境没有可用的 WSL/Linux Bash 而 BLOCKED。
3. Docker CLI 不存在，`docker build`、`docker compose config` 和 Compose acceptance 未运行，因而 BLOCKED。
4. Playwright 真实浏览器 E2E 未运行；仅完成 `--list`，因而 BLOCKED。
5. 没有运行中的路由器、有效运行时秘密和真实 NVIDIA 上游服务，真实 live 联调未运行，因而 BLOCKED。
6. `golangci-lint` 不可用，静态质量门禁 BLOCKED。
7. ASR/TTS 没有真实请求成功证据，且没有通过受审计入口写入 `capability_verified_at`，不能宣称 Audio 能力验收通过。

本报告不包含任何 Key、Cookie、请求正文或响应正文。

判定只使用以下词：

- **PASS：** 有本轮实际命令成功结果，或有可核验的静态实现/提交证据且该项不依赖未执行的外部环境。
- **FAIL：** 已执行并失败，或实现/验收结果与需求不符。
- **BLOCKED：** 当前环境、服务、秘密或工具缺失，导致该项没有形成可接受的通过证据。BLOCKED 不等于 PASS。
- **部分 PASS：** 仅表示局部静态或普通测试证据通过；如果需求还要求 race、Docker、E2E 或 live，则整体仍按 FAIL/BLOCKED 处理。

## 8. 安全、隐私和 Audio 特别说明

1. 第一轮普通 HTTP 风险已在 `README.md`、Linux 部署文档和备份文档中醒目标注：管理员密码、管理员 Cookie、下游 Access Key、提示词和响应会明文传输，当前版本不是安全生产部署。
2. 未通过 `bash scripts/check-secrets.sh` 的完整 tracked 文件扫描前，不能宣称 secret scan PASS。当前 `3447bc4` 仅修复了测试假 Key 扫描匹配问题，不能替代脚本运行证据。
3. `go test ./...` 和 Mock 普通泄漏测试通过，只说明已执行的普通测试通过；不能替代 race、Docker history/镜像扫描或完整 secret scan。
4. ASR/TTS 只能在真实账户、真实模型、真实 endpoint 请求成功，并且成功时间通过受审计流程写入对应模型 `capability_verified_at` 后启用。本轮没有这种证据，因此 Audio `FR-API-006`、`FR-API-007`、`TEST-REAL-007`、`TEST-REAL-008` 均保持 BLOCKED。
5. 禁止通过直接修改 SQLite、伪造时间戳、猜测模型名称或把 Audio `SKIP` 改写成 PASS 绕过门禁。

## 9. 剩余阻断动作

发布前必须在具备 Linux CI 或等价 Linux 工具链的环境完成：

1. 执行 `go test -race ./...`。
2. 执行 `go test -race ./tests/mocknvidia -count=10`，并保留完整成功结果。
3. 执行 `bash scripts/check-secrets.sh`，确认所有 Git tracked 文件扫描通过。
4. 安装 Chromium 并执行 `bash tests/e2e/run.sh`，保留 6 个真实浏览器 E2E case 结果和清理证据。
5. 执行 `docker build -t nvidia-router:acceptance .`。
6. 执行 Docker Compose acceptance：`up -d --wait`、`/health/live`、首次改密前 `/health/ready` 失败、清理容器和 volume，并检查镜像/构建上下文无秘密。
7. 安装固定版本 `golangci-lint`，执行 `golangci-lint run ./...`。

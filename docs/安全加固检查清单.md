# 安全加固检查清单

部署后按本清单逐项核对。清单覆盖传输、会话、密钥、容器与数据五个层面；每一项都有检查命令和通过标准。**应用本身只提供 HTTP**，未配置 HTTPS 反向代理前，任何一项涉及凭据的检查都不算通过。

## 1. 传输层

| 检查项 | 命令 / 配置 | 通过标准 |
| --- | --- | --- |
| 默认只监听回环 | `docker compose ps` 或 `docker compose port app 3756` | 端口绑定为 `127.0.0.1:3756`，不是 `0.0.0.0` 或公网 IP |
| 生产环境有 HTTPS 终结 | 反向代理配置（Nginx/Caddy/Traefik） | 浏览器访问管理面时地址为 `https://`，无混合内容告警 |
| 反向代理只放行必要的转发头 | 代理配置 | 只从可信来源接受 `X-Forwarded-Proto`/`X-Forwarded-For` |

> 普通 HTTP 会明文传输管理员密码、Cookie、下游 Access Key、提示词与响应。第一轮普通 HTTP 部署不是安全生产部署，禁止直接暴露到公网。

## 2. 会话与 Cookie

| 检查项 | 命令 / 配置 | 通过标准 |
| --- | --- | --- |
| HTTPS 下启用 Secure Cookie | `.env` 设 `NVIDIA_ROUTER_ADMIN_SECURE_COOKIE=true` | 登录后浏览器 Cookie 属性含 `Secure` |
| 配置外部 origin | `.env` 设 `NVIDIA_ROUTER_ADMIN_EXTERNAL_ORIGIN=https://<域名>`（不含路径和 query） | 管理页面的 API 请求 Origin 校验通过 |
| 限制可信代理来源 | `.env` 设 `NVIDIA_ROUTER_TRUSTED_PROXY_CIDRS` 为实际反向代理网段 | 伪造 `X-Forwarded-Proto` 的请求不会影响 Cookie 判定 |
| 首次登录强制改密 | 用 `NVIDIA_ROUTER_INITIAL_ADMIN_PASSWORD` 登录 | 登录后必须修改密码，改密前 `/health/ready` 返回失败 |
| 定期轮换管理员密码 | `docker compose run --rm --no-deps app admin reset-password --password '<新密码>'` | 轮换后旧会话全部失效 |

## 3. 密钥管理

| 检查项 | 命令 / 配置 | 通过标准 |
| --- | --- | --- |
| 主密钥强度与保管 | `openssl rand -base64 32 \| tr '+/' '-_' \| tr -d '='` | 32 字节 Raw URL Base64；只存于 vault/密码管理器，不进仓库、Shell history、日志 |
| 主密钥不写入磁盘明文 | `.env` 文件权限 | `.env` 权限为 `600` 且不在版本控制内 |
| 轮转演练 | 按 [备份与恢复说明.md](备份与恢复说明.md) 停服轮转 | 轮转后新版本生效、旧 key 懒迁移完成、恢复演练通过后再清理旧 key |
| XApi 凭据保管 | `NVIDIA_ROUTER_XK_UPSTREAM_URL` 只注入运行时 | 不写入 Git、数据库、日志、文档或 API 响应 |
| 备份加密与分离 | [自动备份方案.md](自动备份方案.md) | 备份与主密钥分开保管，备份文件静态加密或访问受限 |
| 密钥明文驻留内存 | 不适用（代码层面） | 明确风险：NVIDIA Key 与代理 Key 以明文驻留内存直到 GC，进程退出即释放；不要在服务器上开启核心转储后把核心文件外泄 |

## 4. 容器与进程加固

| 检查项 | 配置 | 通过标准 |
| --- | --- | --- |
| 只读根文件系统 | `read_only: true` | 容器内 `/` 不可写；数据只落在 `/data` |
| 放弃 Linux capabilities | `cap_drop: [ALL]` | `docker inspect` 显示无 `CAP_*` 提升 |
| 禁止提权 | `security_opt: [no-new-privileges:true]` | 进程无法通过 setuid 提升权限 |
| 非 root 运行 | 镜像以 UID/GID `10001` 运行（见 [备份与恢复说明.md](备份与恢复说明.md)） | 容器进程用户不是 `root` |
| 临时目录受控 | `tmpfs: /tmp:size=64m,mode=1777` | `/tmp` 不落持久盘、大小受限 |

## 5. 数据与凭证卫生

| 检查项 | 命令 / 配置 | 通过标准 |
| --- | --- | --- |
| 初始化 Access Key 最小权限 | 管理页面创建 | 对下游客户端按需设置 RPM/TPM/并发与过期时间，不共用一把 key |
| Access Key 泄露应急 | 管理页面"撤销" | 撤销立即生效（认证缓存清空）；确认后从客户端移除该 key |
| 泄露后轮换 Key | 创建新 key 替换旧 key | 旧 key 撤销后不再被使用 |
| 日志脱敏 | 检查 `/var/log` 与应用日志 | 日志不包含主密钥、代理认证 Key、Access Key 明文、管理员密码 |
| 数据保留 | 运行设置页配置日志保留天数 | `request_logs` 定期清理，避免长期累积敏感元数据 |

## 6. 上线前快速检查

```bash
# 端口只监听回环
docker compose port app 3756

# 容器能力与特权
docker inspect -f '{{.Config.CapDrop}} {{.HostConfig.Privileged}}' "$(docker compose ps -q app)"

# 就绪检查（改密完成后）
curl --fail http://127.0.0.1:3756/health/live
curl --fail http://127.0.0.1:3756/health/ready
```

如果任意一项不满足，禁止把服务对外提供或接入生产客户端。

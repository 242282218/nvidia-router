## 一、语言重写评估（结论）

**不需要换语言。Go 是这类项目的最优解，且当前实现已是同类项目的优秀水平。**

| 方案 | 结论 |
|---|---|
| 保持 Go（现状） | ✅ 推荐。流式转发 / CONNECT / 高并发 JSON 处理正是 Go 强项；单二进制 + Docker 部署天然契合 |
| Python（LiteLLM 路线） | ❌ 性能差 1-2 个数量级，流式高并发下 GC 与 GIL 是硬伤 |
| Node.js | ❌ IO 密集适合，但本项目 CPU 热点（JSON 解析、HMAC、SSE 逐事件处理）不如 Go |
| Rust | ❌ 理论收益集中在内存与 JSON 解析（<15%），维护成本高、开发慢，个人维护项目不划算 |

前端 Vue3 + TS 无需变动。真正该做的是模块内优化（见问题清单）。

## 二、对标优秀项目调研摘要

| 项目 | 架构要点 | 可借鉴设计 |
|---|---|---|
| one-api / new-api | 渠道模型 + ability 映射、(group, model) 随机取渠道；`shouldRetry` 仅对 429/5xx 换上游重试、同上游不重试；滚动成功率队列（10 次、阈值 0.8）自动禁用渠道；预扣配额失败返还；SQLite `BATCH_UPDATE_ENABLED` 每 5s 批量写；流式逐行缓冲上限 64MiB | 滚动成功率自动禁用 + 换渠道重试组合；body/流缓冲硬上限 |
| LiteLLM | 路由策略可插拔（simple-shuffle / latency-based / least-busy / usage-based）；按 deployment 独立冷却，429 立即冷却 5s、分钟失败率 >50% 冷却 5s；到期后**渐进重新引入**；`num_retries` 可 per-request 覆写；把 provider SDK `max_retries` 钉为 0 防 (1+N)² 放大 | 冷却渐进恢复；同组换成员 vs 跨组 fallback 分层；按错误类型分别配置重试/冷却 |

### 架构层可借鉴项（对标优秀项目，按优先级）

1. **出口分级 / backup 语义**（对标 gost backup、LiteLLM weighted failover）：被 429/5xx 风暴打中但仍健康的出口降为备用档，仅主档耗尽才使用，主档恢复即撤回——比纯 EWMA 排序更抗"同批 IP 同时失效"抖动
2. **冷却渐进恢复**（对标 LiteLLM gradually reintroduce）：ejectionWindow 到期后先以低频探测观察若干成功样本再恢复全量，避免刚恢复的坏出口立刻再爆
3. **按错误类型区分冷却阈值**（对标 LiteLLM AllowedFailsPolicy）：429（key 级配额）阈值更高且不隔离出口，5xx（目标故障）隔离阈值单独调低；529 已按池级处理
4. **重试/冷却事件指标**：`/metrics` 补 `retry_attempts`、`proxy_ejection/restore` 计数器（当前只有成功/失败/取消分桶）
5. **保池策略**（对标 proxy_pool）：`healthy < expected_qty` 时缩短采集间隔/提前下一轮采集，把保池从"失败后补救"变成"主动防跌穿"
6. **限流响应头标准化**（对标 Kong）：429 时补 `RateLimit-Limit/Remaining/Reset`，客户端可原生自适应退避
7. **多实例限流升级路径**（低优先，仅记录设计）：按 Kong 三档 policy + new-api Redis 计数设计，把现有内存限流隔离为 local 档，避免返工

## 四、值得肯定的部分（勿改动）

- transport 按超时参数池化复用 + LRU（direct/proxy 双路径）✅
- SSE 纯流式转发无中间全量缓冲、4MiB 事件/行硬上限 ✅
- 队列等待 buffered(1) channel + abandon 竞态处理，无等待者 goroutine ✅
- 锁内无网络 IO（池/管理器读多写少用 RWMutex，状态值语义出锁）✅
- EWMA 双轨（探针/真实请求）质量分、Grace 续命锚定 ValidatedAt 防无限续命 ✅
- SQLite WAL + 读写池分离 + `_txlock=immediate` + busy_timeout，观测写缓冲批处理 ✅
- 密钥加密纪律：HKDF 派生、AAD 绑定、HMAC 摘要替代明文、轮换单事务+离线约束 ✅
- 每请求 AEAD 解密恰好 1 次，其余为廉价 HMAC ✅
- 配置热路径无锁（atomic.Value）、迁移校验和 + 版本校验 ✅

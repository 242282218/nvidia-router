# 生产兼容、key 调度与空响应稳定性实现计划

> **面向 AI 代理的工作者：** 依据 `docs/superpowers/specs/2026-08-16-Responses核心兼容优化设计.md`，在当前已有未提交改动上局部实现；不回退 `responses.go` 的 Body 生命周期修复，不提交或推送。

**目标：** 让 Responses 核心文本/函数工具路径可被 Codex 生产使用，并对每个 NVIDIA key 实施可验证的请求速率保护，避免空 200 响应。

**架构：** Responses 继续复用现有 ModelCatalog、Attempt、Pool、Proxy 和 NVIDIA Chat 链路。Pool 在内存中维护每 key 的滚动请求时间窗，所有候选耗尽时返回带 Retry-After 的 429；上游空响应在提交客户端响应前被识别为可重试故障。

**技术栈：** Go 标准库、现有 SQLite/HTTP/SSE 实现、现有 Vitest/Playwright 测试，不新增依赖或数据库迁移。

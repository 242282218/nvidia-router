# 监控与详细日志实现计划

> 面向 AI 代理的工作者：必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（- [ ]）语法来跟踪进度。

**目标：** 在现有 SQLite 观测链上提供至少 30 天的请求元数据留存、24 小时/7 天/30 天趋势、请求级筛选分页和安全错误监控。

**架构：** 保留 HTTPMiddleware → BufferRecorder → request_logs/daily_stats 写入链，只增加日聚合首字节字段、监控查询索引和只读 API。管理台在现有 /statistics 路由升级为监控页，使用原生 SVG/CSS 绘图，不引入外部监控服务或前端图表依赖。

**技术栈：** Go、SQLite、database/sql、Vue 3 Composition API、TypeScript、UnoCSS、Vitest、Go 标准测试工具。

    type MonitoringFilter struct {
        ModelID, Endpoint, Outcome, Search string
        Status *int
        AccessKeyID, NVIDIAKeyID *int64

        Filter MonitoringFilter
    }

    type MonitoringSnapshot struct {
        Range string
        From, To time.Time
        Summary MonitoringSummary
        Series []MonitoringSeriesPoint
    }

    type RequestLog struct {
        RequestID, Endpoint string
        ModelID *string
        AccessKeyID, NVIDIAKeyID *int64
        HTTPStatus int
        Outcome string
        ErrorCode, UpstreamRequestID *string
        IsStream bool
        QueueMS, DurationMS, AttemptCount int64
        FirstByteMS, PromptTokens, CompletionTokens *int64
        CreatedAt string
    }

    type RequestLogsQuery struct {
        MonitoringQuery
        Page, PageSize int
    }

    type RequestLogsPage struct {
        Items []RequestLog
        Page, PageSize int
        Total int64
        HasMore bool
    }

    type MonitoringStore interface {
        MonitoringSummary(context.Context, MonitoringQuery) (MonitoringSnapshot, error)
        ListRequestLogs(context.Context, RequestLogsQuery) (RequestLogsPage, error)
    }

- [ ] 步骤 4：实现聚合查询

MonitoringSummary 的查询策略固定为：24 小时使用 request_logs 按 UTC 小时分组；7 天和 30 天在没有 endpoint/status/search 且筛选至多一个维度时读取 daily_stats；其他筛选从 request_logs 按时间索引查询。所有查询在 Go 中补齐空桶，并使用加权总和计算平均值。

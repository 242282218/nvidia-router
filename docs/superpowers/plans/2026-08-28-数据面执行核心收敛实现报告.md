# 数据面执行核心收敛实现报告

## 实现状态

第一阶段已完成，代码停留在分支 `codex/optimize-executor-20260828`，未提交、未部署、未重启远端服务。本阶段只收敛 OpenCodeFree Chat/Responses 的请求生命周期，不改变公开端点、数据库结构、模型能力门控或 Responses 支持边界。

## 变更文件

- `internal/httpapi/v1/opencodefree_execution.go`
  - 新增共享 OCF 执行器，统一 attempt context、一次重试、500ms 等待、状态码映射和响应 body 关闭。
  - 404 映射 `upstream_model_not_found` 且不重试；429 映射 `upstream_unavailable` 且不重试；5xx/436 首次可重试一次，436 最终映射 502。
  - 2xx callback 返回 `upstream_empty_response` 或 `upstream_protocol_error` 时，仅在客户端尚未写出时重试一次。
  - 使用幂等 body wrapper，避免协议 callback、取消 goroutine 与执行器重复关闭底层 transport body。
  - 请求 context 在 attempt 完成后取消；重试等待期间 parent context 取消时静默结束，保持客户端取消语义。

- `internal/httpapi/v1/chat.go`
  - `serveOpenCodeFree` 改为共享执行器的 Chat 适配器，保留现有非流式校验、流式截断、错误 code 和 provider 未配置语义。
  - 删除旧的 `openCodeFreeOnce` 循环及重复状态分类函数。
  - `firstWriteTracker.Flush` 将隐式 header/flush 视为已提交，阻止不安全重放。

- `internal/httpapi/v1/responses_opencodefree.go`
  - `serveOpenCodeFreeResponses` 改为共享执行器的 Responses 适配器。
  - 保留 Chat 校验、Responses SSE 状态机和 Chat→Responses 非流式转换；转换失败标记为本地不可重放协议错误。
  - 删除旧的 `openCodeFreeResponsesStatus` 生命周期实现。

- `internal/httpapi/v1/opencodefree_execution_test.go`
  - 新增共享策略测试：404、429、503、436、2xx 空/协议错误、body 关闭、首字节前重试、首字节后禁止重试和取消静默结束。

- `internal/httpapi/v1/chat_test.go`
  - 强化 OCF 流测试，断言重试后的首个 Chat 内容仍到达客户端。

## 第二阶段：请求准备核心

第二阶段已完成，仍停留在本地未提交分支，未部署、未重启远端服务。Chat 与 Responses 继续保留各自协议解析、body lease、响应转换和 provider 分支；共同的模型解析与上游请求准备已收敛到同包内部 `prepareModelRequest`。

### 变更文件

- `internal/httpapi/v1/request_prepare.go`
  - 定义 Chat/Responses 共用的最小 `modelRequest` 接口和 `preparedModelRequest` 结果。
  - 按既有顺序执行模型/stream 观测、requested reasoning 观测、`ModelResolver.Resolve`、能力错误码记录、`modelError` 映射、`MarshalForWithOptions` 及 effective reasoning/source/wire 观测。
  - 准备器不持有 provider、不解析原始 JSON、不写响应；任一 Resolve 或 Marshal 失败都会在进入 provider 分支前返回。
  - 不复制已由协议 marshaller 产生的 body，适配器按只读使用，避免大请求（例如图像输入）在热路径产生额外几十 MiB 拷贝。

- `internal/httpapi/v1/chat.go`
  - Parse 成功后统一调用准备器，并使用返回的 model/body/stream 进入原有 OCF 或 NVIDIA 路径；保留 body lease、错误映射、超时和 provider 调用顺序。

- `internal/httpapi/v1/responses.go`
  - Parse 成功后统一调用准备器，继续执行 Responses response ID、`ResponseConfig`、hosted/stateful 能力边界和 Chat→Responses 转换；未改变公开错误契约。

- `internal/httpapi/v1/request_prepare_test.go`
  - 先以未实现准备器的红灯测试锁定契约，再覆盖成功、Resolve 失败能力错误码、Marshal 失败、stream/body 结果、requested/effective reasoning source/wire 字段和失败时不进入后续调用的边界。

- `internal/httpapi/v1/chat_test.go`、`internal/httpapi/v1/responses_test.go`
  - 增加 Chat/Responses 集成回归断言：同一模型 Resolve 结果、client reasoning source、上游 model ID 与 effective reasoning wire 值均正确传递。

## 第三阶段：Responses OCF 流式 deadline 透传与降级

第三阶段修复了共享首写跟踪器包装后丢失 `http.ResponseWriter` 可选能力的问题，并补齐了 Responses SSE 在不支持写 deadline 的 writer 上的安全降级。代码仍停留在本地未提交分支，未部署、未重启远端服务。

### 变更文件

- `internal/httpapi/v1/chat.go`
  - `firstWriteTracker` 增加 `Unwrap() http.ResponseWriter`，使 `http.ResponseController` 能够继续发现底层 `SetWriteDeadline` 等能力；不改变首写状态记录或重试门控。

- `internal/httpapi/v1/responses.go`
  - `responsesSSEEmitter` 缓存 deadline 不支持状态；`SetWriteDeadline`/`FlushWithDeadline` 遇 `sse.ErrWriteDeadlineUnsupported` 时转为 watchdog + 普通 `Flush`，避免首个 Responses 事件在支持范围内被错误映射成 500。
  - 支持 deadline 的 writer 仍按事件刷新并清理 deadline；watchdog 生命周期保持原有 stall 保护。

- `internal/httpapi/v1/responses_test.go`
  - 更新不支持 deadline 的 emitter 语义测试，新增 OCF Responses stream 在 deadline-capable 与 unsupported writer 两类 writer 上的回归测试，均断言首事件、`response.completed` 和 `[DONE]` 到达且 HTTP 200。

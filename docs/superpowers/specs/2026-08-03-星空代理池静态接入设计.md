# 星空代理池静态接入设计（已废弃）

> 历史设计。当前正式架构是 `nvida反代` 单体内置 XApi 采集器、代理池和 CONNECT；本文件中的独立 HTTP 正向代理配置不得用于部署。

## 目标

让 `nvida反代` 作为客户端连接 `D:\PROJECT_ZZZZZZZZZ\星空代理池` 提供的标准 HTTP 正向代理，不再向星空 XApi 提取单个 `IP:PORT`，也不在本项目内维护代理 IP 的 TTL、续租和数据库覆盖配置。

## 方案选择

1. **静态正向代理连接（采用）**：通过环境变量配置代理池地址和代理认证 Key，NVIDIA 请求统一经过该地址。代理池负责 XApi、代理轮换、测活和过期处理。
   - 优点：职责清晰、请求链路短、不会重复提取或与代理池争抢租期；两个项目可独立部署。
   - 代价：`nvida反代` 不再知道每个出口 IP，故障恢复依赖代理池的健康检查和自身重试。
2. **继续由 `nvida反代` 提取 IP**：保留原 API URL 和租约管理，仅把提取结果交给代理池。
   - 放弃原因：重复实现代理池能力，仍受提取频率、签名和出口白名单影响，无法达到本次“代理池接入”的目标。
3. **共享文件或数据库传递代理地址**：两个进程共享池内代理记录。
   - 放弃原因：引入跨项目存储协议和并发一致性问题，耦合高于标准 HTTP 代理。

## 配置与认证

新增两个运行时环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `NVIDIA_ROUTER_XK_PROXY_URL` | 空 | 星空代理池的 HTTP/HTTPS 正向代理地址，例如 `http://proxy-pool:8080`；为空时直连 NVIDIA |
| `NVIDIA_ROUTER_XK_PROXY_AUTH_KEY` | 空 | 代理池的 `PROXY_AUTH_KEY`；代理地址非空时必填，只从环境变量读取 |

代理池固定要求 Basic 用户名 `proxy`。`nvida反代` 在内存中将其与认证 Key 组成代理认证，不把认证 Key 写入 URL、SQLite、日志、错误响应或管理 API。

代理地址只允许绝对 `http`/`https` URL，禁止 userinfo、query、fragment；允许 Docker 服务名和私网地址，因为该地址是部署者显式配置的内部服务端点。

## 运行链路

```text
NVIDIA 请求
  -> nvidia.Client
  -> xkproxy.Manager.Acquire
  -> http.Transport.Proxy = 星空代理池地址
  -> Proxy-Authorization: Basic proxy:<PROXY_AUTH_KEY>
  -> 星空代理池选择健康出口并访问 NVIDIA
```

`xkproxy.Manager` 只负责构造和复用带代理认证的 `http.Transport`。不同运行时超时配置使用独立 Transport 缓存；底层传输失败时丢弃对应 Transport，保留现有客户端最多一次、且仅在请求尚未写出时的安全重试语义。它不再请求任何 API、不解析 `IP:PORT`、不维护租约时间。

## 删除范围

- 删除 XApi fetcher、API URL/query 校验、单 IP 租约、TTL/续租配置和负缓存。
- 删除代理配置的数据库 Repository、Service、Switcher 以及 `/admin/api/proxy` 管理接口和前端配置页。
- 删除旧的真实 XApi 联调脚本及 CI 入口。
- 保留历史数据库迁移文件作为已发布迁移记录，避免已有数据库因 migration ledger 出现未知版本；新代码不再读取 `xk_proxy_settings`。

## 测试与验收

- 配置测试覆盖：空配置直连、有效代理池 URL、缺失认证 Key、URL 携带凭据/query/fragment/错误 scheme。
- Manager 测试覆盖：代理地址、Basic 认证、Transport 复用、关闭和重试后重新建 Transport；断言认证 Key不会出现在错误和日志中。
- NVIDIA 集成测试覆盖：所有请求经 HTTP CONNECT 代理到 TLS 上游、代理认证错误不会直连、代理连接失败仍返回 `upstream_proxy_unavailable`。
- 删除旧 API 的生产代码、配置和活动文档引用后，运行 `go test ./...`、`go vet ./...`、前端 lint/typecheck/test/build、Compose 配置检查和 secret scan。

## 部署约定

两个项目独立 Compose 部署时，将它们接入同一个 Docker 网络，或把代理池暴露到 `nvida反代` 可访问的地址；`NVIDIA_ROUTER_XK_PROXY_URL` 使用该可达地址，`NVIDIA_ROUTER_XK_PROXY_AUTH_KEY` 使用代理池 `.env` 中的同一 Key。代理池未就绪时，`nvida反代` 必须报代理不可用，不得静默直连。

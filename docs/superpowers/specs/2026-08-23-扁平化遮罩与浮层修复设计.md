# 扁平化遮罩与浮层修复设计

## 目标

在不改动业务接口和路由行为的前提下，修复前端浮层在窄屏、边缘位置和固定布局中的裁切/遮挡问题，并将视觉统一为 Flat Outline：层级只由色面、描边、间距和状态色表达，不再使用拟物阴影、光晕、模糊或材质遮罩。

## 已确认的范围

- 目标范围为 web/src 的全站管理界面及其生产嵌入产物 internal/web/dist。
- 模态框、命令面板、快捷键帮助和移动侧栏仍保留功能性 scrim；scrim 不使用 backdrop-filter 或 blur。
- 1px 描边、状态点、浅色状态底色和必要的交互过渡属于扁平界面的一部分，保留。
- 图表面积渐变和骨架屏 shimmer 仅作为数据/加载表达保留，不作为卡片材质或投影效果。
- 不重写后端、API、数据库、路由协议，不引入新的浮层库，不把现有组件整体迁移到 Portal。
- 工作区已有未提交改动属于用户现有工作，实施时只在其基础上追加本任务变更，不执行 reset、checkout 或批量恢复。

## 现状根因

1. ModelHealthCard.vue 通过固定 70px 边界夹逼 tooltip 横坐标，并强制 whitespace-nowrap；长文案在卡片边缘或窄屏上会越过可视区域。
2. ChartArea.vue 和 UiTooltip.vue 的提示面板虽然有左右翻转，但缺少统一的视口宽度上限和可换行策略。
3. UiMenu.vue 使用局部绝对定位，没有最大高度和内部滚动约束，菜单内容较长或父容器空间不足时可能被裁切。
4. 固定层的高度约束不统一：弹窗、命令面板、快捷键帮助需要针对移动视口的 dvh 和安全区补齐滚动边界。
5. 代码和主题残留了 animate-ping、认证页网格 mask、阴影 token/工具类以及与“浮起”感相关的装饰性过渡。

## 方案与取舍

### 方案 A：扁平基线 + 共享约束 + 定点修复（采用）

沿用现有 Vue 组件边界，只在主题 token、UnoCSS shortcuts、共享浮层和实际越界的图表/模型卡片上修复。通过 CSS 最大尺寸、内部滚动和边缘感知定位解决根因。

优点：改动集中、不会改变现有 DOM 查询和焦点管理契约、可以覆盖桌面与 390px 视口。代价：不提供一个可处理所有未来浮层的通用定位引擎。

### 方案 B：只改视觉 token

删除阴影和 blur，保留现有浮层定位。

优点：改动最少。缺点：不能修复 tooltip/menu 的真实裁切问题，因此不满足本任务。

### 方案 C：全量 Portal 浮层系统

将菜单、tooltip、弹窗全部挂到 body，通过实时测量实现固定定位。

优点：理论上最强的层级隔离。缺点：需要重做焦点、测试和调用方边界，改动明显超出本任务，且会增加新的定位状态与生命周期风险。

## 设计

### 1. Flat Outline 视觉基线

- 删除主题中的阴影 token 及所有 shadow-*、box-shadow、text-shadow、drop-shadow、backdrop-blur、装饰性 glow 和材质 mask。
- 卡片、菜单、弹窗、toast、批量操作条使用 background + border 区分层级。
- 认证页删除固定装饰网格和径向 mask，保留纯色背景、品牌标记和实色表面。
- 异常状态保留静态状态点和文案，删除 animate-ping；不再用脉冲或缩放模拟实体浮起。
- 保留键盘焦点的 outline，不使用低对比度阴影替代焦点提示。

### 2. 浮层边界契约

- 统一保证浮层面板 min-width: 0、max-width: calc(100vw - 2rem)、overflow-wrap: anywhere；紧凑 badge 在可预测情况下保持单行，不可预测 token 允许换行。
- UiTooltip、图表 tooltip 和模型健康 tooltip 使用边缘感知的 start/center/end 对齐，不把固定像素作为唯一边界；面板在窄屏下不得超出视口。
- UiMenu 增加 max-height、overflow-y-auto 和 overscroll-behavior: contain，保持现有 top-start/bottom-end 调用契约。
- UiModal、命令面板和快捷键帮助的外层使用可滚动的 min-h-dvh 布局，面板设置移动视口高度上限；内部内容继续独立滚动，避免固定层遮住焦点。
- 固定 toast 和批量操作条保留安全区偏移，并通过宽度约束避免覆盖移动端主要内容。
- 保留当前 z-index 层级关系：移动 scrim < drawer/header，菜单/toast < modal/command/help，tooltip 位于其宿主内容之上；不新增全局层级管理器。

### 3. 数据和交互行为

- 仅改变浮层几何、可读性和视觉样式，不改变 tooltip 文案、菜单动作、Esc 关闭、点击外部关闭、焦点归还和 body scroll lock。
- 现有 useDialog、useScrollLock 继续作为焦点和滚动锁定的单一来源。
- 对 reduced motion 保持现有行为；扁平化不移除必要的状态反馈。

## 验收标准

### 视觉

- web/src 活跃代码和 UnoCSS shortcuts 中不再出现阴影、模糊、光晕或装饰性 mask；允许的图表/骨架渐变有明确语义。
- 桌面端页面、弹窗、菜单、toast 和账户菜单采用 Flat Outline，无投影、无玻璃感、无材质纹理。
- 认证页和异常状态点不产生灰色/彩色光晕。

### 布局与可访问性

- 1440px 桌面和 390px 移动视口的 scrollWidth 不超过 clientWidth。
- 打开移动侧栏、命令面板、快捷键帮助和模态框时，面板完整位于可视区域内；Tab 焦点仍可见，Esc 和点击外部关闭仍有效。
- tooltip、menu 的内容不被卡片、viewport 或固定层裁切；长 token 允许换行或有可操作的完整值入口。

### 工程验证

- 相关 Vitest 先出现预期失败，再以最小实现通过。
- eslint、vitest run、vue-tsc --noEmit、vite build、git diff --check 通过。
- internal/web/dist/index.html 只引用本次构建生成的资源，静态资源闭包检查通过。
- Playwright 在桌面三列与 390px 单列完成截图和 DOM/几何断言。

## 不在本次范围

- 不调整 API、数据库、部署、生产环境和真实代理联调。
- 不重做整站色彩、字体或信息架构。
- 不为未来浮层场景预先引入定位库、状态管理或全局 overlay manager。

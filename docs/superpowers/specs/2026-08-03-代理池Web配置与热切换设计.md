# 代理池 Web 配置与热切换设计

## 状态

已确认设计，作为本次实现的边界基线。

## 背景

`nvida反代` 当前通过 `NVIDIA_ROUTER_XK_PROXY_URL` 和
`NVIDIA_ROUTER_XK_PROXY_AUTH_KEY` 在进程启动时配置星空代理池。代理 Manager
在启动阶段创建，Web 只管理队列、超时和故障转移参数，无法修改代理池地址或认证
Key。

本次增加管理员 Web 配置能力，同时保持代理认证 Key 不明文落库、不通过 API
返回、不进入日志，并保持代理启用时禁止静默直连的安全边界。

## 目标与非目标

目标：

- 在管理员 Web 中查看和修改代理池地址、启用状态和认证 Key。
- 认证 Key 使用现有主密钥加密写入 SQLite。
- 配置保存后对新 NVIDIA 请求立即生效，不要求手动重启。
- 正在执行的请求继续使用切换前的传输，避免中途断开。
- 保留现有环境变量作为没有数据库配置时的启动兜底。

非目标：

- 不把代理池的 XApi、代理出口 IP、TTL 或租约逻辑移回本项目。
- 不在 Web 中显示认证 Key 明文。
- 不增加代理池健康探测、出口列表或自动重试策略；这些仍由代理池和现有
  NVIDIA 客户端负责。

## 方案选择

1. **加密 SQLite + 热切换（采用）**：Web 保存配置，认证 Key 用主密钥 AEAD
   加密，运行中的 Provider 原子替换。新请求立即使用新配置，当前请求保持旧
   Handle。改动集中且符合已有 SQLite、主密钥和 `xkproxy.Provider` 边界。
2. **写入环境变量文件并重启**：实现量较小，但需要管理文件权限、进程重启和
   平台差异，且容易留下明文凭据；放弃。
3. **加密 SQLite 但保存后重启生效**：运行时改动较小，但 Web 保存后的状态与
   实际请求路径在重启前不一致；放弃。

## 数据模型与密钥保护

新增迁移 `internal/database/migrations/006_proxy_pool_settings.sql`，保留
历史 `003_xk_proxy_settings` 迁移不变。新表只允许一行：

```sql
CREATE TABLE proxy_pool_settings (
  id INTEGER PRIMARY KEY CHECK (id = 1),
  enabled INTEGER NOT NULL CHECK (enabled IN (0, 1)),
  proxy_url TEXT NOT NULL DEFAULT '',
  auth_key_nonce BLOB,
  auth_key_ciphertext BLOB,
  version INTEGER NOT NULL DEFAULT 1,
  updated_at TEXT NOT NULL,
  CHECK ((auth_key_nonce IS NULL AND auth_key_ciphertext IS NULL)
      OR (auth_key_nonce IS NOT NULL AND auth_key_ciphertext IS NOT NULL)),
  CHECK (enabled = 0 OR (proxy_url <> '' AND auth_key_ciphertext IS NOT NULL))
);
```

代理 URL 不包含凭据、query、fragment 或路径，可明文保存；认证 Key 使用
`crypto.KeySet.Encrypt` 加密，固定 AAD 为 `proxy-pool-auth-key:v1`。API 和日志
只返回 `auth_configured` 布尔值。清除认证 Key 时删除 nonce 和 ciphertext；启用
代理必须重新提供有效 Key。

## 配置优先级与启动

- 存在数据库行时，数据库配置优先于环境变量；`source` 返回 `database`。
- 没有数据库行时，使用现有环境变量配置；`source` 返回 `environment`。
- 两者都没有时使用直连；`source` 返回 `none`。
- 环境变量配置首次被 Web 保存时写入数据库并成为后续重启的优先配置。
- 显式提供的环境变量仍先按启动配置校验；若 URL、认证 Key 配对不完整或 URL
  非法，服务拒绝启动，即使数据库已有配置，避免用 Web 配置掩盖部署错误。
- 数据库密文无法用当前主密钥解密时，服务启动失败，不得静默退回直连。

代理配置服务负责读取、校验、加密、持久化和应用配置；HTTP Handler 不直接
操作数据库或 Manager。

## 运行时热切换

新增 `xkproxy.Switcher`，实现现有 `xkproxy.Provider` 接口并持有当前
`Manager`：

- `Acquire` 在读锁内取得当前 Manager，然后按现有逻辑创建或复用 Transport。
- 应用新配置前先校验 URL、认证 Key 并创建新 Manager；创建失败时不写库、不
  改变当前配置。
- 数据库写入成功后原子替换当前 Manager，再关闭旧 Manager 的 idle 连接。
- 旧 Handle 不因切换立即失效，正在进行的请求可以正常完成。
- 禁用代理时切换为 direct 状态；这是管理员显式选择，允许直连。
- 启用代理时 Manager 不可用仍返回 `upstream proxy unavailable`，不回退直连。
- 应用关闭时统一关闭 Switcher 和当前 Manager。

## 管理 API

新增受管理员管理权限保护的 `/admin/api/proxy-pool`：

```json
GET response:
{
  "data": {
    "enabled": true,
    "proxy_url": "http://127.0.0.1:8080",
    "auth_configured": true,
    "source": "database"
  }
}
```

```json
PATCH request:
{
  "enabled": true,
  "proxy_url": "http://127.0.0.1:8080",
  "auth_key": "new-key",
  "clear_auth_key": false
}
```

`auth_key` 为空表示保留已有 Key；`clear_auth_key` 只能在禁用代理时使用。
启用时，合并已有 Key 后必须满足认证 Key 非空。URL 校验复用启动配置的协议、
host、路径、query、fragment 和 userinfo 约束。错误响应只指出字段和通用原因，
不得回显认证 Key。

## Web 交互

在现有管理侧栏增加“代理池”页面，沿用当前深色控制台的颜色、间距、SVG 图标
和响应式布局。页面包含：

- 启用代理池开关。
- 代理地址输入框和 URL 格式说明。
- 密码类型的认证 Key 输入框；空值提示“留空保持现有 Key”。
- `已配置` / `未配置` 状态，不展示 Key 内容。
- 保存和清除 Key 操作，保存成功显示“新请求立即使用此配置”。

字段使用可见 label、键盘可聚焦控件、字段旁错误提示和禁用态反馈；移动端以
单列排列，不引入新的 UI 依赖或视觉主题。

## 错误处理与安全验收

- 非法 URL、启用时缺 Key、清除 Key 时仍启用、数据库密文损坏均有明确失败结果。
- 保存前创建新 Manager，任何校验、加密或数据库失败都保留旧配置和旧连接。
- API 响应、日志、前端状态和错误文本不得包含认证 Key。
- 代理切换后的新请求必须带 `Proxy-Authorization: Basic proxy:<key>`；代理
  连接失败不能产生直连请求。
- 迁移升级、加密往返、API 权限、热切换并发、前端表单和现有全量回归均需通过。

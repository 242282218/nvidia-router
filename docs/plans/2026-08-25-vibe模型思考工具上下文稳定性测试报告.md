## 3. 维度结果

### 思考强度与 thinking 开关

- `reasoning_low/medium/high` 共 12 个用例，10 个 HTTP 200；NVIDIA Nemotron 的 `medium/high` 各返回 502 `upstream_proxy_unavailable`。
- `thinking_enabled/thinking_disabled` 共 8 个用例，7 个 HTTP 200；NVIDIA Nemotron 的 `thinking_disabled` 返回同类 502。
- 3 个 OpenCodeFree 模型的思考档位请求均返回 200，思考字符数随模型和档位变化，但不能跨模型比较强弱。

### 流式

- 4 个模型各执行 1 次流式请求，4/4 返回 200、完整结束事件，`sse_malformed=0`。
- 已补测工具流式响应：两个支持工具的模型均返回完整 SSE；工具增量数量由上游模型决定，x-preview 出现多次工具增量，不能简化为一次调用假设。

### 工具

- 声明支持工具的模型为 `opencode-free/nemotron-3-ultra-free` 和 `opencodefree/x-preview-f-free`。
- Nemotron：`auto` 和具名工具调用参数合法；流式工具返回 2 个调用；固定工具结果回传一次返回 502 `upstream_protocol_error`；`required` 请求返回了普通终答而没有工具调用。
- x-preview：`auto/required/named` 均返回合法工具调用；流式工具请求完成；固定工具结果回传返回 200 并产生终答。
- 本轮没有观察到 `not_implemented`；工具能力应继续按模型记录，不能从路由器整体可用推断所有模型均支持 Agent 闭环。

### 上下文与长输出

- 长输入用例约 8K 字符，只验证请求能够进入上游并返回，不据此推断 32K 或 128K 安全窗口。
- 长输入：NVIDIA Nemotron、OCF Nemotron、Hy3 返回 200；Hy3 以 `finish_reason=length` 结束且可见内容为空；x-preview 返回 503 `upstream_unavailable`。
- 输出预算 `64/512/2048` 共 12 个用例，7 个 HTTP 200：NVIDIA 3/3、Hy3 3/3、OCF Nemotron 1/3、x-preview 0/3。
- Hy3 在 64/512 小预算下出现思考字符但没有可见终答；这是预算与模型声明档位的交互现象，不应判作上下文窗口失败。
- OCF Nemotron 的 64 token 用例返回上游协议错误，2048 token 用例在客户端 45 秒超时。

### 重复稳定性

- 每个模型串行重复 5 次，共 20 次：HTTP 200 为 16/20。
- NVIDIA Nemotron 4/5；Hy3 5/5 但其中 1 次可见内容为空；OCF Nemotron 4/5，1 次客户端超时；x-preview 3/5，2 次上游 503。
- 该样本用于发现瞬态问题，不等价于长时间压力测试或统计置信区间。

### JSON 与代码任务

- 两个支持工具模型均执行 JSON 对象兼容请求并返回 200；本轮保留结构化状态和长度，不保留正文。
- 对 `opencode-free/nemotron-3-ultra-free` 执行 2 个代码任务：生成 `merge_intervals`、修复 `running_average`。两次均返回 200、代码块存在、AST 语法解析通过且目标函数存在。
- 代码探针没有执行模型生成代码，避免将不可信输出直接运行在测试机上。

## 4. 日志与根因分析

对容器最近 2 小时日志只做签名计数，不输出原始日志：

| 签名 | 次数 | 解释 |
|---|---:|---|
| `validation_all_failed` | 192 | 代理池出口验证波动 |
| `proxy_rejected` | 12 | CONNECT/出口被拒 |
| `proxy_transport_retired` | 73 | 失败出口被回收 |
| `transport_failed` | 5 | 传输层失败 |
| `foreign` | 1 | 与模型健康探测外键竞态相符 |
| `panic/fatal/migration` | 0 | 未发现进程崩溃或迁移失败 |

根因结论：

1. **代理出口波动**：请求级 502 `upstream_proxy_unavailable`、503 `upstream_unavailable` 与日志中的验证失败、出口拒绝和 transport retire 同时出现，并且按模型/时段变化；当前证据指向上游代理出口和 provider 可用性，不指向路由器崩溃。
2. **模型健康探测外键竞态**：reader 先取得模型快照，探测期间管理端删除模型，writer 记录事件时 `models` 行已不存在，SQLite 外键约束失败。当前工作树中的修复将该错误归类为 `ErrModelDeleted` 并跳过过期快照，回归测试已覆盖并通过；远端旧镜像尚未包含这份未提交改动。
3. **小预算空回复**：Hy3 的目录只声明 `low/high`，测试脚本仍显式发送 `reasoning_effort=none`；在 32/64/512 等小预算下，思考消耗预算后以 `length` 结束。该现象不能直接当作上下文或路由失败，后续探针应尊重每个模型声明的 reasoning levels。
4. **上游协议错误和超时**：OCF Nemotron 的部分输出/工具回传用例是 502 `upstream_protocol_error` 或客户端超时；x-preview 的长请求、输出和重复用例是 503 `upstream_unavailable`。这些属于上游响应协议/可用性问题，当前没有服务内部 panic 或迁移错误证据。

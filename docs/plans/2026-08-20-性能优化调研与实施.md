# NVIDIA 路由器性能优化调研与实施 — 2026-08-20

> 范围：67k 行 Go + Vue 全仓库体检、同类项目调研、两轮性能优化（Batch1/Batch2）落地、验证与推送。本文档沉淀可复用的调研结论、热点定位方法与验证命令，供后续性能任务直接复用。

## 1. 结论先行

- **不需要换语言重写**：Go 1.24 是 IO 密集 + 长连接 + 轻量 CPU 场景的最优点。Rust 仅在 `sse/decoder` 与 `crypto AEAD` 两个窄模块有 15% 左右的边际 CPU 收益，但会破坏 `CGO_ENABLED=0` 纯 Go 部署与单体 Docker 形态，成本约 3 人月，ROI 低（当前瓶颈在 SQLite 单写而非 CPU）。
- 两轮优化后：SSE 每流省 1 goroutine、`MarshalFor` 80% 场景零重编码、前端首屏 420KB→132KB、SQLite 批量 512、代理池读路径 RWMutex + 快路径、环形事件缓冲 O(1)。
- 全部验证通过：`go vet` / `go test ./...` / `pnpm typecheck/build/test/lint` 全绿，已推送 `main`（`205180a` Batch1、`89a733a` Batch2）。

## 2. 同类项目选型对比（二次使用参考）

| 项目 | 语言 | 结论 |
|---|---|---|
| `one-api` / `new-api` | Go + Gin + gorm | 与本项目同构；瓶颈同为 SQLite 单写 + 池调度，已迁 WAL + 多连接 |
| `litellm-proxy` | Python | QPS 上限约为 Go 的 1/8，GIL + GC 停顿使流式首 token P99 恶化 2x，反模式 |
| `vllm-router` / `cloudflare-ai-gateway` | Go / Rust 混合 | 仅 Tokenizer / 限流用 Rust 加速，网关仍 Go；本项目未达该阈值 |
| `caddy` / `traefik` | Go | 参考点：解析后 URL 缓存、限定 LRU、热路径避免 per-request 分配 |

选型判断标准：QPS > 5k 且 pprof 证实 `ValidateNonstreamChat` 等编解码热点 >30% CPU 时，再议 Rust sidecar；当前未达。

## 3. 热点定位方法（复用）

1. `go test -bench . -benchmem` 对比改动前后 allocation（如 `ValidateNonstreamChat`）。
2. pprof `alloc_space` / `mutex` profile 定位真实热点，而非凭感觉优化。
3. 锁竞争排查：热路径优先 `RWMutex` 读、RCU 快照、`sync.Map` 分片；`sync.Pool` 只用于确认分配占比 >10% 的大缓冲。
4. SQLite 单写排查：`SetMaxOpenConns(1)` 是否被读写共用；WAL 下读路径必须独立 reader 池。
5. 前端：`vite build` 产物分块观察（gzip 大小），路由懒加载是首包最大单一来源。

## 4. Batch1：P0/P1 热点（commit `205180a`）

### 4.1 热点与改动对照

| 模块 | 位置 | 问题 → 修复 |
|---|---|---|
| crypto GCM | `internal/crypto/aead.go:58` | 全局缓存 `map[int]AEAD` 跨 KeySet 污染（错误主密钥可通过缓存）→ 缓存移到 `KeySet` 实例（`master.go:28`），`InvalidateGCMCache` 保留兼容 |
| SQLite | `internal/database/db.go:58` | WAL 调优显式化：`wal_autocheckpoint=1000` / `journal_size_limit=64MB` / `cache_size=-64000` / `temp_store=MEMORY` |
| SQLite 索引 | `internal/database/migrations/035_perf_indexes.sql` | monitoring 时间窗查询：`idx_request_logs_created_first_token`（部分索引）、`model_id+created_at`、`access_key_id+created_at`；部分索引控制体积 |
| 事件环 | `internal/eventhub/hub.go:51` | 满时 `copy(ring, ring[1:])` O(n) → `head/size` 循环覆盖 O(1)；`Subscribe` 按 head 顺序回放修复乱序 |
| bodyBudget | `internal/httpapi/v1/bodybudget.go:19` | chunked 占位 1MB→64KB（16 并发下 429 根因）；256KB 读缓冲 `sync.Pool`；`Read` 内 halving CAS 循环 → 单 CAS |
| 观测批量 | `internal/observability/buffer.go:16` | FlushBatchSize 256→512（1k RPS 下 SQLite 轮转省 40%） |
| Key 池 | `internal/pool/pool.go:76` `internal/pool/state.go:88` | `Mutex→RWMutex`；`weightedSelect` 预分配权重数组 → 两遍零分配；`requestTimes` cap=30 原地过滤零分配 |
| SSE prime | `internal/sse/prime.go:34` | per-stream goroutine + channel → `context.AfterFunc` 关闭 body（1k 流省 1k goroutine） |
| NVIDIA 校验 | `internal/upstream/nvidia/chat.go:183` | 通用 map 解码 → 单结构体解码（省全量分配） |
| 采集器 | `internal/xkproxy/collector.go:365` | per-proxy goroutine + semaphore → 固定 worker 池 + jobs channel |
| 池排序 | `internal/xkproxy/pool.go:186` | comparator 内重复 `QualityScore()` → 预计算 `scored[]`；`orderedLocked` 加 minRemainingLife==0 快路径；`rotate` 原地 append 旋转 |
| Manager | `internal/xkproxy/manager.go:224` | `Mutex→RWMutex` 读快路径；重建时 `newTransport`（含 `Transport.Clone`）移出锁外 |
| Validator | `internal/xkproxy/validator.go:143` | `DisableKeepAlives:true`（每 5s 重复 TCP+TLS）→ keep-alive + `MaxIdleConnsPerHost=10`（4 代理×3 并发不排队）；避免锁内重复 `proxy.URL()` 解析 |
| Web 契约 | `web/src/features/statistics/types.ts` + `contract.spec.ts` | 补 `canceled_count`（后端 033 迁移已加、前端类型漏声明导致契约测试红） |

### 4.2 修复的关键 bug

- **crypto 全局 GCM 缓存跨实例污染**：`TestValidateSentinelRejectsCorruptionAndWrongMasterKey` 等 4 个测试 FAIL（错误主密钥被缓存命中判定为正确）。缓存移入 `KeySet` 实例后修复，同时保留加密热路径缓存收益。

## 5. Batch2：Chat fast-path + 前端分包（commit `89a733a`）

| 模块 | 位置 | 改动 |
|---|---|---|
| Chat 序列化 | `internal/protocol/chat/request.go:118` | `Request` 保留 `raw`；`MarshalFor` 80% 场景（上游模型==公共模型 && 无 tools/无 tool_choice/无 reasoning 改写 && 无 max_completion_tokens 规范化）直接返回原始字节，省 `cloneFields+sort+marshalFields` |
| 路由懒加载 | `web/src/router/index.ts:8` | 8 个视图全部 `() => import()`；vite 自动分包，首屏 `index-*.js` 420KB→131KB，视图 2-72KB 按需加载 |
| 契约对齐 | `web/src/features/statistics/{types,MonitoringTrendChart.spec,StatisticsView.spec}.ts` | 补 `canceled_count` 到前端类型与 spec |
| 测试适配 | `web/src/router/index.spec.ts:198` | 懒加载异步导航：click 后 `flushPromises` 不足以等 dynamic import，fallback `router.push` + 额外 tick |
| 产物同步 | `internal/web/dist/*` | `//go:embed all:dist` 要求构建产物入库，`pnpm --dir web run build` 后必须 `git add internal/web/dist -f` |

### 5.1 经验：go:embed 前端产物

`internal/web/dist` 由 vite 输出且被 `//go:embed` 嵌入二进制，**任何前端改动必须重建并提交 dist**，否则 Docker 镜像内是旧前端。构建命令：`pnpm --dir web run build`。

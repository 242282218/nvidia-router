## 一、方法

对全部 13 个 enabled 模型先做**现场门控**（1 次小请求，35s 超时，并发 4），按"现阶段能稳定测试"原则选出通过门控的 4 个模型（NVIDIA 2 + OpenCodeFree 2），再跑 5 维度矩阵（模型间并行、模型内串行、预算硬超时）：

| 维度 | 用例 | 观测点 |
|---|---|---|
| 思考强度 | none / low / high（流式） | reasoning_chars 单调性、关断确定性、预算占用 |
| 工具 | 并行双工具、流式工具、多轮闭环 | finish_reason、tool_calls 完整性、args 合法性、终答回引 |
| 上下文 | ~24K 字符 needle recall、2048 token 长输出 | 答案正确性、finish_reason、时延 |
| 稳定性 | 3 次流式重复 | 成功率、TTFT、流内最大空档 |
| 指令遵循 | `response_format=json_object` | 严格 JSON、字段正确 |

### 工具调用明细（仅 nemotron-3-ultra-free 通过）

- 并行：一条消息同时返回 `get_weather` + `get_time`，`finish_reason=tool_calls`，id 完整、arguments 合法 JSON（`{"city":"Beijing"}` / `{"timezone":"Tokyo"}`），3.4s。
- 流式：tool_calls 增量完整，`[DONE]` 到达，空档 0.3s。
- **多轮闭环**：回传工具结果后终答正确引用两个值（"21°C and sunny"、"2026-08-22T12:00:00+09:00"），`finish_reason=stop`，18.4s。

### 上下文明细

- 输入侧：4 个模型对 ~24K 字符（约 6-8K token）预填充全部 200，耗时 3.8–6.1s，无拒绝。
- needle recall：仅 kimi-k3 在 max_tokens=64 下精确命中（`ZEBRA-42-VECTOR`）；m3 / nemotron-free / x-preview 的 64 token 预算被思考消耗，内容为空或 3 字符截断——**是预算现象，不是上下文失败**（与既有结论"思考吃小预算"一致）。
- 长输出（max_tokens=2048）：kimi-k3 5114 字符/stop/93.5s ✅；x-preview 1354 字符/length/61s（75% 预算烧在思考）；m3 与 nemotron-free 100s 超时 ❌。

## 四、横向发现（按优先级）

1. **P0 · `z-ai/glm-5.2` 上游 410 Gone**：曾是最推荐模型（工具 6/6），现基础请求稳定 410。白名单仍 enabled + supports_tools=true，会持续产生用户可见失败。
2. **P0 · 能力元数据漂移（声明非推理、实际思考）**：`kimi-k3`、`x-preview-f-free` 声明 `supports_reasoning=false`，实测默认输出 `reasoning_content`（小请求 68–121 字符、长任务 6100 字符）。路由器对"显式关断 + 非推理模型"会剥离 effort 字段，模型仍默认思考 → 小 `max_tokens` 场景内容为空、`finish_reason=length`。与 memory 已记 P0/P1 同源问题一致，本轮新增两个模型证据。
3. **P1 · 工具 501（Agent 客户端必挂）**：`kimi-k3`、`m3`、`x-preview` 对 tools 请求本地 0ms 501 `not_implemented`。Claude Code/Cline 类客户端默认带 tools，这些模型直接不可用。其中 **m3 历史实测支持工具**（08-16 no-gate 部署时 200 + tool_calls），属元数据未回写。
4. **P1 · auto-reasoning 注入非法档位打挂 hy3-free**：`auto_reasoning_enabled=1` 会给 `supports_reasoning=true` 模型的无 effort 请求注入档位；hy3-free 上游仅接受 `no_think/low/high`，注入值被 400 拒绝 → 网关 502。auto-reasoning 的取值集合未按模型线格式归一。
5. **P1 · nemotron-free 间歇截断流**：本轮 12 次请求中 2 次（reasoning_high、stability_2）HTTP 200 但流在首个事件后关闭，无 `[DONE]`/finish/内容。客户端表现为空响应。历史也出现过一次同类 `upstream_protocol_error`，非孤立。
6. **P2 · m3 json_object 间歇空对象**：一次精确 JSON、一次 `{}`（仍为合法 JSON），非确定性。
7. **P2 · context_length 全量缺失**：13 个模型 DB 与 `/v1/models` 均为 NULL，vibe 客户端无法做压缩决策（迁移 042 已支持手工维护，尚未填值）。
8. **长生成是当前共性短板**：2048 token 生成只有 kimi-k3 在 ~94s 内完成；m3/nemotron-free 100s 超时、x-preview 75% 预算被思考消耗。

# 公网双服务部署说明（hangzhou2-2）

目标：在 `114.55.25.190`（别名 `hangzhou2-2`）上公网部署：

- `nvidia-router` 反代：公网 `0.0.0.0:3756`
- `star-proxy-pool` 代理池：公网 `0.0.0.0:18080`（独立 Compose 项目）

两者通过 Docker 外部网络 `router-internal` 互通，反代以
`http://proxy-pool:8080` 访问代理池（`proxy-pool` 为网络别名），不绕宿主公网。

> 2026-08-11 实际部署采用「两个独立 Compose 项目 + 共享外部网络」：
> 反代项目 `nvidia-router` 在 `/opt/nvidia-router-releases/<tag>`，
> 代理池项目 `star-proxy-pool` 在 `/opt/star-proxy-pool`。仓库内的
> `docker-compose.public.yml` 是单项目双服务的备选方案，未用于本次部署。

## 前置条件

- 本机到目标机 SSH 可用：`ssh -F ssh_config_local hangzhou2-2`
- 目标机已安装 Docker 与 Docker Compose v2
- 已创建外部网络：`docker network create router-internal`
- 反代容器通过 `docker network connect --alias proxy-pool router-internal <池容器>`
  获得 `proxy-pool` 别名；重新创建代理池容器后需重连网络与别名。
- 真实密钥文件：
  - 反代 `/opt/nvidia-router-releases/<tag>/.env`：`NVIDIA_ROUTER_MASTER_KEY`、
    `NVIDIA_ROUTER_INITIAL_ADMIN_PASSWORD`、`NVIDIA_ROUTER_XK_PROXY_URL`、
    `NVIDIA_ROUTER_XK_PROXY_AUTH_KEY`
  - 代理池 `/opt/star-proxy-pool/.env`：`PROXY_AUTH_KEY`、`ADMIN_AUTH_KEY`、
    `UPSTREAM_API_URL`、`VALIDATION_URL` 等

> 密钥不进入 Git。两份 `.env` 权限应为 `600`。

## 部署（实际命令）

```bash
# 1) 构建并启动代理池（公网 18080）
cd /opt/star-proxy-pool
env -u COMPOSE_FILE -u COMPOSE_PROJECT_NAME docker compose \
  --project-directory /opt/star-proxy-pool -p star-proxy-pool \
  -f /opt/star-proxy-pool/compose.yaml up -d --force-recreate

# 2) 连接外部网络并挂 proxy-pool 别名
docker network connect --alias proxy-pool router-internal star-proxy-pool-proxy-pool-1

# 3) 构建并启动反代（公网 3756）
cd /opt/nvidia-router-releases/<tag>
env -u COMPOSE_FILE -u COMPOSE_PROJECT_NAME docker compose \
  --project-directory /opt/nvidia-router-releases/<tag> -p nvidia-router \
  -f docker-compose.yml -f docker-compose.remote.yml up -d --force-recreate
```

## 回滚

```bash
# 反代回滚：恢复旧镜像标签并强制重建
env -u COMPOSE_FILE -u COMPOSE_PROJECT_NAME docker compose \
  --project-directory /opt/nvidia-router-releases/<旧tag> -p nvidia-router \
  -f docker-compose.yml -f docker-compose.remote.yml up -d --force-recreate
# 数据卷恢复：从 backups/ 用 alpine tar 恢复 nvr-data / pool-data
```

## 注意事项

- 公网为 HTTP，无 HTTPS；认证信息在传输中可被窃听，生产上线前应加独立网关。
- 代理池 `PROXY_AUTH_KEY` / `ADMIN_AUTH_KEY` 至少 16 字符，不与旧公网实例（18081）复用。
- 反代与代理池容器重建后需重新执行 `docker network connect --alias proxy-pool`。
- UFW 对 `18080/tcp` 已放行；旧公网实例 `18081`（9router 依赖）保持不动。

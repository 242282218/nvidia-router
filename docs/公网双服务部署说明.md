# 公网双服务部署说明（hangzhou2-2）

目标：在 `114.55.25.190`（别名 `hangzhou2-2`）上部署单体路由器：

- `nvidia-router` 反代：公网 `0.0.0.0:3756`
- 内置代理池：与路由器同进程运行，不暴露独立 HTTP 代理端口。

> 旧版本曾采用双服务部署；升级到当前版本后，运行时 XApi 只注入路由器容器。

## 前置条件

- 本机到目标机 SSH 可用：`ssh -F ssh_config_local hangzhou2-2`
- 目标机已安装 Docker 与 Docker Compose v2
- 已创建外部网络：`docker network create router-internal`
- 反代容器通过 `docker network connect --alias proxy-pool router-internal <池容器>`
  获得 `proxy-pool` 别名；重新创建代理池容器后需重连网络与别名。
- 真实密钥文件：
  - 反代 `/opt/nvidia-router-releases/<tag>/.env`：主密钥、初始管理员密码和运行时
    `NVIDIA_ROUTER_XK_UPSTREAM_URL`；完整 XApi 地址不得进入 Git、数据库或日志。

> 密钥不进入 Git。两份 `.env` 权限应为 `600`。

## 部署（实际命令）

```bash
# 构建并启动单体路由器（公网 3756）
cd /opt/nvidia-router-releases/<tag>
env -u COMPOSE_FILE -u COMPOSE_PROJECT_NAME docker compose \
  --project-directory /opt/nvidia-router-releases/<tag> -p nvidia-router \
  -f docker-compose.yml -f docker-compose.public.yml up -d --force-recreate
```

## 验证

```bash
curl -fsS http://127.0.0.1:3756/health/live
curl -fsS http://127.0.0.1:3756/health/ready
curl -fsS http://127.0.0.1:3756/health/ready
```

端到端验证（真实模型）：

```bash

  -d '{"model":"deepseek-v4-flash","messages":[{"role":"user","content":"say OK"}],"stream":true}' \
  http://127.0.0.1:3756/v1/chat/completions
```

## 稳定性实测

```bash
ROUTER_BASE=http://127.0.0.1:3756 ACCESS_KEY=<ak> bash scripts/test/run-deepseek-stability.sh 1800 2
```

模型固定 `deepseek-v4-flash`（反代 015 迁移映射到 `deepseek-ai/deepseek-v4-flash-0731`）。

## 回滚

```bash
# 反代回滚：恢复旧镜像标签并强制重建
env -u COMPOSE_FILE -u COMPOSE_PROJECT_NAME docker compose \
  --project-directory /opt/nvidia-router-releases/<旧tag> -p nvidia-router \
  -f docker-compose.yml -f docker-compose.remote.yml up -d --force-recreate
# 数据卷恢复：从 backups/ 用 alpine tar 恢复 nvr-data / pool-data
```

## 注意事项

- 公网为 HTTP，无 HTTPS；认证信息在传输中可被窃听，生产上线前应加独立网关。
- 旧代理池容器可在确认无其他业务依赖后单独下线；不要让路由器回退到旧外部代理。
- 公网端口只有路由器 `3756`；XApi 凭据仅注入路由器运行时。

# 公网双服务部署说明（hangzhou2-2）

目标：在 `114.55.25.190`（别名 `hangzhou2-2`）上公网部署：

- `nvidia-router` 反代：公网 `0.0.0.0:3756`
- `star-proxy-pool` 代理池：公网 `0.0.0.0:18081`

两者通过 Docker 外部网络 `router-internal` 互通，反代以
`http://proxy-pool:8080` 访问代理池，不绕宿主公网。

## 前置条件

- 本机到目标机 SSH 可用：`ssh -F ssh_config_local hangzhou2-2`
- 目标机已安装 Docker 与 Docker Compose v2
- 已创建外部网络：`docker network create router-internal`（脚本会自动创建）
- 真实密钥文件：
  - `.env`：反代所需 `NVIDIA_ROUTER_MASTER_KEY`、`NVIDIA_ROUTER_INITIAL_ADMIN_PASSWORD`、
    `NVIDIA_ROUTER_XK_PROXY_AUTH_KEY`
  - `pool.env`：代理池所需 `PROXY_AUTH_KEY`、`ADMIN_AUTH_KEY`、`UPSTREAM_API_URL`、
    `VALIDATION_URL` 等

> 密钥不进入 Git。部署目录的 `.env`/`pool.env` 权限应为 `600`。

## 部署

```bash
# 在部署目录（含本仓库的 docker-compose.yml 与 docker-compose.public.yml）
./scripts/deploy/deploy-public.sh
```

脚本会：构建镜像 → 校验密钥文件 → 确保外部网络 → 创建并授权 `pool-data/`
（代理池 UID 10001 可写）→ 备份数据卷 → 显式 Compose 启动 → 验证两个健康端点。

代理池镜像优先使用 `POOL_IMAGE` 环境变量，其次本地 `star-proxy-pool/Dockerfile`
构建；两者都没有时跳过构建并继续。

## 回滚

```bash
./scripts/deploy/rollback-public.sh deploy-20260810-204300
```

按传入镜像标签强制重建，并从 `backups/<最新>/` 恢复 `nvr-data` 与 `pool-data` 卷。

## 稳定性验收

真实 30 分钟流式实测（DeepSeek V4 Flash）：

```bash
ROUTER_BASE=http://127.0.0.1:3756 ACCESS_KEY=<测试ak> \
  bash scripts/test/run-deepseek-stability.sh 1800 2
```

脚本输出每请求 JSON 行（状态 / TTFT / 总耗时）与 Markdown 汇总，不记录密钥与正文。

## 安全注意事项

- 反代与代理池均为公网 HTTP 入口，无 HTTPS；认证信息在传输中可被窃听。
  上线生产前应加独立 HTTPS 网关并收敛公网端口。
- 代理池 `PROXY_AUTH_KEY` / `ADMIN_AUTH_KEY` 至少 16 字符，且不与公网旧实例复用。
- 代理池管理接口（`/admin/*`、`/readyz`、`/metrics`）需 `X-API-Key`；`/healthz` 开放。
- UFW 对 `18081/tcp` 建议加 `LIMIT` 限速。

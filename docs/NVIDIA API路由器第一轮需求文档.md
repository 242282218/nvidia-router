## 2. 背景

本项目用于构建一个专用的 NVIDIA API 路由器。路由器管理多个合法的 NVIDIA Build API Key，通过轮询、限流感知、冷却和故障转移，将下游 OpenAI-compatible 请求代理到 NVIDIA Build 托管 API。

第一轮以个人使用为主，提供 Web 管理页面、多个下游访问 Key、NVIDIA Key 池、模型白名单、基础运行统计和 Docker 部署能力。项目不在第一轮发展为通用多厂商 AI 网关，也不实现公开多租户、计费和复杂权限系统。

## 3. 产品目标

### 3.1 核心目标

1. 通过单一 OpenAI-compatible API 地址访问 NVIDIA Build 模型。
2. 管理多个 NVIDIA API Key，并在健康 Key 之间进行限流感知轮询。
3. 在限流、临时网络错误和部分上游故障时自动切换 Key。
4. 支持 Chat Completions、Responses、Embedding 和 NVIDIA 可映射的 Audio 接口。
5. 提供 Web 管理页面，完成 Key、模型、运行状态和基础统计管理。
6. 确保 NVIDIA Key、下游访问 Key和请求内容不会以明文形式写入数据库或日志。
7. 以单台 Linux 服务器和 Docker Compose 为第一轮部署目标。

### 3.2 成功标准

第一轮完成后，应满足以下结果：

- OpenAI SDK 能通过本服务调用 NVIDIA 模型。
- 普通聊天和 SSE 流式聊天均可正常工作。
- `/v1/responses` 能完成文本、函数工具、普通响应和流式事件转换。
- 多个 NVIDIA Key 能按既定调度规则轮询，并正确处理忙碌、冷却、禁用和模型不可用状态。
- 管理员能通过 Web 页面管理 NVIDIA Key、下游访问 Key 和模型白名单。
- 服务可通过 Docker Compose 在单台 Linux 服务器运行。
- 核心主路径经过真实 NVIDIA API Key 联调，错误和边界场景经过 Mock 自动化测试。

## 4. 范围与边界

### 4.1 第一轮包含范围

- NVIDIA Build 托管 API 代理。
- OpenAI-compatible API。
- Chat Completions 普通和流式响应。
- Responses API 文本、函数工具、普通和流式响应。
- Embedding。
- Audio Transcriptions。
- Audio Speech。
- NVIDIA Key 池和限流感知轮询。
- 全局模型白名单。
- Web 管理页面。

- SQLite 持久化。
- Docker Compose 单实例部署。
- 健康检查、基础统计、日志脱敏、CLI 备份和密码重置。

### 4.2 第一轮排除范围

以下能力明确延期，不属于第一轮：

- HTTPS、证书、Caddy、Nginx 或其他反向代理设计。
- 团队成员、邀请、角色和成员权限。
- 成员配额、计费和支付。
- OpenAI、Anthropic、Gemini 等其他 AI 上游。
- 图片、文件、Batch、Assistants 等无法直接映射到 NVIDIA 的 OpenAI API。
- Responses API 的有状态能力。
- `previous_response_id`。
- background 模式。
- OpenAI 内置工具。
- 远程 MCP。
- 响应正文持久化。
- 多实例部署和 Kubernetes。
- Prometheus 指标。
- 周期性后台 NVIDIA Key 健康巡检。

## 5. 最终决策覆盖说明

需求讨论过程中存在两项早期方案，现以最终决策为准：

1. **用户范围：** 不再按完整受信小团队首版实现，改为个人使用优先，同时在数据结构上预留未来团队扩展空间。
2. **模型范围：** 不再按多个 Key 的动态模型交集生成 `/v1/models`，改为管理员维护稳定的全局模型白名单，并在内部记录 Key 与模型的不可用关系。

## 6. 总体业务流程

```text
OpenAI-compatible 客户端
        |
        | Bearer 下游访问 Key
        v
NVIDIA API 路由器
        |
        +-- 客户端鉴权
        +-- API 请求校验和必要转换
        +-- 模型白名单校验
        +-- 全局队列
        +-- 限流感知 Key 轮询
        +-- 首字节前故障转移
        +-- JSON / SSE 响应转换
        |
        | Bearer NVIDIA API Key
        v
NVIDIA Build 托管 API
```

## 7. 对外 API 需求

### 7.1 通用约定

- API 前缀为 `/v1`。
- 下游客户端通过 `Authorization: Bearer <访问 Key>` 鉴权。
- 错误响应采用 OpenAI 风格的结构化错误格式。
- 未实现的 `/v1/*` 接口必须返回明确的不支持错误，不得通配转发到 NVIDIA。
- 路由器不得向下游暴露 NVIDIA API Key。
- 客户端断开连接后，应立即取消对应的上游请求。

### 7.2 模型列表

#### 接口

```http
GET /v1/models
```

#### 要求

- 返回管理员配置的全局模型白名单。
- 不直接返回任意单个 NVIDIA Key 的完整模型列表。
- 不因新增 NVIDIA Key 自动改变已保存的白名单。
- 禁用模型不得继续对外展示。

### 7.3 Chat Completions

#### 接口

```http
POST /v1/chat/completions
```

#### 要求

- 支持非流式 JSON 响应。
- 支持 `stream: true` 的 SSE 响应。
- 支持 NVIDIA 当前可映射的 OpenAI Chat Completions 字段。
- 支持 system、user、assistant 和 tool 相关消息。
- 支持 function tools 和 `tool_choice`。
- 支持 NVIDIA 模型可用的 reasoning 参数。
- 流式请求和非流式请求使用 NVIDIA 对应的 Chat Completions 上游接口。
- 一旦向客户端发送首个响应字节，不得切换 Key 并重放请求。

### 7.4 Responses API

#### 接口

```http
POST /v1/responses
```

#### 转换流程

```text
Responses 请求
  -> 归一化为 NVIDIA Chat Completions 请求
  -> 调用 NVIDIA
  -> 转换为 Responses 对象或 Responses SSE 事件
```

#### 支持范围

- `instructions`。
- 文本 `input`。
- 多轮输入。
- reasoning 参数。
- function tools。
- `tool_choice`。
- 非流式 Responses 对象。
- 流式 Responses SSE 事件。
- 函数参数增量事件。

#### 不支持范围

- `store: true`。
- `previous_response_id`。
- background 模式。
- 文件和图片输入。
- OpenAI 内置工具。
- 远程 MCP。
- 服务端响应状态查询和恢复。

客户端发送 `store: true` 时，服务必须明确拒绝，不得静默忽略，也不得让客户端误以为响应已经持久化。

### 7.5 Embedding

#### 接口

```http
POST /v1/embeddings
```

#### 要求

- 将合法请求转发到 NVIDIA 对应的 Embedding API。
- 使用当前调度选中的 NVIDIA Key。
- 校验目标模型是否在全局白名单中。
- 保持 OpenAI-compatible 的请求和响应形状。
- 对 NVIDIA 已知不兼容字段执行必要修正。

### 7.6 Audio Transcriptions

#### 接口

```http
POST /v1/audio/transcriptions
```

#### 要求

- 支持 NVIDIA 当前提供且可映射的 ASR 模型。
- 正确处理 multipart 请求。
- 不保存上传的音频文件或转录正文。
- 请求结束、失败或客户端取消后及时释放临时资源。

### 7.7 Audio Speech

#### 接口

```http
POST /v1/audio/speech
```

#### 要求

- 支持 NVIDIA 当前提供且可映射的 TTS 模型。
- 正确处理文本、模型、声音和输出格式参数。
- 不保存输入文本和生成音频。
- 已向客户端输出音频字节后，不得切换 Key 重放请求。

### 7.8 未支持接口

- 未支持的 `/v1/*` 路径返回结构化 `501`。
- 不得把未知路径原样转发到 NVIDIA。
- 错误信息应说明接口当前不受支持，但不得泄漏内部地址、密钥或堆栈。

## 8. 请求转换策略

采用“白名单修正 + 未知字段透传”策略。

### 8.1 必须处理的内容

- 模型 ID 和模型别名。
- `stream`。
- Chat Completions 与 Responses 的必要结构转换。
- NVIDIA 已知不兼容的 thinking/reasoning 字段。
- function tools 和 `tool_choice`。
- 接口必填字段和基本类型。

### 8.2 透传原则

- 未知但合法的 JSON 字段默认原样传递给 NVIDIA。
- 不得因为本服务尚未认识新字段就无条件删除该字段。
- 明确与 NVIDIA 不兼容的字段可以修正、删除或拒绝。
- 修正规则应集中维护并可测试，不应散落在 HTTP Handler 中。

## 9. NVIDIA Key 管理

### 9.1 Key 录入

管理页面支持：

- 单个添加 NVIDIA Key。
- 批量粘贴，每行一个 Key。
- 添加前格式校验。
- 数据库内去重。
- 调用 NVIDIA `/v1/models` 进行在线验证。
- 仅保存验证有效且不重复的 Key。

### 9.2 批量导入结果

- 批量导入允许部分成功。
- 有效项正常入库。
- 无效项不入库。
- 页面按输入行返回失败原因。
- 无效 Key 不得保存在数据库、日志或错误详情中。

### 9.3 Key 展示

- 管理页面只显示 Key 掩码、可识别前缀或后缀。
- 不提供 NVIDIA Key 明文查看功能。
- 不提供 NVIDIA Key 明文导出功能。
- Key 明文只能在导入请求处理期间短暂存在于内存中。

### 9.4 Key 状态

每个 NVIDIA Key 至少具有以下状态：

- 启用。
- 手工停用。
- 忙碌。
- 限流冷却。
- 临时故障冷却。
- 鉴权失效。
- 对特定模型不可用。

### 9.5 Key 状态持久化

服务重启后保留：

- 管理员手工启停状态。
- 鉴权失效状态。
- `429` 冷却截止时间。
- 连续失败等关键故障状态。
- Key 与模型不可用关系。

服务重启后重置：

- 当前活跃请求数。
- 等待队列。
- Round Robin 游标。

## 10. 模型白名单

### 10.1 初始化

- 添加首个有效 NVIDIA Key 后，读取该 Key 的 `/v1/models`。
- 管理员在返回模型中勾选需要开放的模型。
- 勾选结果保存为全局模型白名单。

### 10.2 后续维护

- 新增 Key 不得自动新增或删除白名单模型。
- 管理员可手动启用或禁用白名单模型。
- 下游只能调用白名单中的模型。
- `/v1/models` 仅返回白名单中的启用模型。

### 10.3 Key 与模型不可用关系

当某个 Key 对白名单模型返回明确的无权限或不可用错误时：

1. 不禁用整个 Key。
2. 记录该 Key 与目标模型的不可用关系。
3. 当前请求在首字节前继续尝试其他 Key。
4. 后续调用该模型时跳过该 Key。
5. 管理员可通过手动测试清除或更新该状态。

第一轮不运行周期性后台探测。添加 Key、真实请求和管理员手动测试是状态更新来源。

## 11. Key 调度

### 11.1 调度算法

健康 Key 采用限流感知 Round Robin：

- 通过轮询游标保持基本公平。
- 跳过手工停用 Key。
- 跳过鉴权失效 Key。
- 跳过冷却中的 Key。
- 跳过当前忙碌 Key。
- 跳过对目标模型不可用的 Key。

### 11.2 并发限制

- 每个 NVIDIA Key 最大并发固定为 `1`。
- 长时间 SSE 请求会持续占用对应 Key。
- Key 只有在请求完成、失败或取消后才释放。
- 不允许为了处理池满而突破单 Key 并发限制。

### 11.3 单次请求尝试范围

- 单个请求可以遍历全部候选 Key。
- 同一个 Key 对同一请求最多尝试一次。
- 换 Key 不得重置客户端请求的总超时预算。
- 达到总超时、客户端取消或没有候选 Key 时立即停止尝试。

## 12. 故障分类和转移

### 12.1 允许换 Key 的情况

仅在尚未向客户端发送首个响应字节时，以下错误允许尝试下一个 Key：

- 上游连接失败。
- 响应头或首字节超时。
- NVIDIA 返回 `429`。
- 可恢复的 NVIDIA `5xx`。
- 当前 Key 对目标模型明确无权限或不可用。

### 12.2 不允许盲目重试的情况

- 请求参数错误。
- 模型不在白名单中。
- 下游鉴权失败。
- 其他可确定为请求本身问题的 `4xx`。
- 已经向客户端发送响应字节的流式请求。

### 12.3 分类冷却

- `429`：优先读取并遵循 `Retry-After`；缺失时采用指数退避。
- `401/403`：当错误被判定为 Key 整体鉴权失效时，停用该 Key，等待管理员处理。
- 模型级权限错误：只记录 Key 与模型不可用关系。
- 网络错误和 `5xx`：进入短暂冷却，后续真实请求进行半开探测。

分类器必须区分 Key 整体鉴权失败和单模型权限失败，避免错误地禁用整个 Key。

## 13. 队列与超时

### 13.1 全局队列

当所有候选 Key 都忙碌时，请求进入全局 FIFO 队列。

默认参数：

| 参数 | 默认值 |
|---|---:|
| 队列容量 | 100 |
| 最长等待时间 | 60 秒 |

要求：

- 参数可通过管理页面修改。
- 队列满时返回 OpenAI 风格 `429`。
- 等待超时时返回 OpenAI 风格 `429`。
- 返回 `Retry-After`。
- 客户端断开后立即从队列移除。
- 第一轮不实现按成员公平队列。

### 13.2 分阶段超时

默认参数：

| 阶段 | 默认值 |
|---|---:|
| 建立上游连接 | 10 秒 |
| 等待响应头或流式首字节 | 60 秒 |
| 非流式请求总时长 | 5 分钟 |

要求：

- 超时参数允许后续配置。
- 超时预算属于整个客户端请求。
- 换 Key 不得重新获得完整预算。
- 客户端断开后立即取消上游请求。
- 超时后释放 Key 占用和相关临时资源。

## 14. 管理员和下游访问 Key

### 14.1 管理员初始化

- 初始账号为 `admin`。
- 初始密码为 `admin`。
- `admin/admin` 只能用于首次登录。
- 首次登录后必须立即修改密码。
- 修改密码前禁止使用代理 API。
- 修改密码前禁止执行 NVIDIA Key 添加等敏感管理操作。
- 管理员密码使用 Argon2id 哈希保存。

### 14.2 管理员会话

- 管理员会话固定有效 24 小时。
- 主动退出后会话立即失效。
- 修改密码后撤销全部既有会话。
- 管理员可执行“注销全部会话”。
- 会话 Cookie 使用 HttpOnly。
- 在第一轮普通 HTTP 部署下无法依赖 Secure Cookie，此限制必须在部署文档中明确说明。

### 14.3 密码恢复

- 不提供公网“忘记密码”接口。
- 通过容器内 CLI 重置管理员密码。
- 重置密码时撤销全部管理员会话。
- 重置管理员密码不得删除、重置或重新加密 NVIDIA Key。

### 14.4 下游访问 Key

- 支持创建多个下游访问 Key。
- 每个 Key 可填写设备或客户端名称。
- 明文只在创建成功时展示一次。
- 数据库只保存不可逆哈希、前缀和元数据。
- 支持单独撤销。
- 记录创建时间和最后使用时间。
- 第一轮不配置模型权限、接口权限或成员配额。

## 15. Web 管理页面

### 15.1 设计目标

- 桌面端优先。
- 手机端可完成查看、启停和基础管理。
- 不要求手机端完整优化所有高级表格操作。

### 15.2 页面功能

#### 登录与安全

- 管理员登录。
- 首次登录强制改密。
- 修改密码。
- 主动退出。
- 注销全部会话。

#### NVIDIA Key 管理

- 单个添加。
- 批量粘贴导入。
- 启用和停用。
- 删除。
- 单个手动测试。
- 测试全部 Key。
- 查看掩码、状态、最近错误和冷却截止时间。
- 查看 Key 与模型不可用状态。

#### 下游访问 Key 管理

- 创建。
- 创建后一次性显示明文。
- 查看名称、前缀、创建时间和最后使用时间。
- 撤销。

#### 模型管理

- 从首个有效 Key 导入模型候选列表。
- 勾选并保存全局模型白名单。
- 启用或禁用模型。
- 查看模型相关 Key 可用状态。

#### 运行状态

- NVIDIA Key 总数。
- 健康、忙碌、冷却、停用和失效 Key 数量。
- 当前活跃请求数。
- 当前队列长度。
- 队列容量和等待时间配置。
- 最近错误。

#### 基础统计

- 请求总量。
- 成功和失败数量。
- 基础成功率。
- 请求耗时。
- 重试次数。
- 模型维度基础统计。
- NVIDIA Key 维度基础统计。
- 下游访问 Key 维度基础统计。
- NVIDIA 响应提供时记录 token 用量。

第一轮不实现完整分析平台、计费报表或复杂自定义仪表盘。

## 16. 数据存储

### 16.1 数据库

- 使用 SQLite。
- 开启 WAL 模式。
- 使用版本化数据库迁移。
- 数据库文件保存在 Docker 持久化挂载卷中。
- 第一轮不同时支持 PostgreSQL。

### 16.2 NVIDIA Key 加密

- NVIDIA Key 必须可逆加密后保存。
- 使用环境变量提供 32 字节主加密密钥。
- 使用 AEAD 加密方案。
- 数据库保存密文、nonce、掩码信息和状态，不保存明文。
- 主密钥缺失时拒绝启动。
- 主密钥错误、无法解密现有数据时拒绝启动。
- 不得静默生成新主密钥覆盖已有配置。

### 16.3 下游 Key 存储

- 下游访问 Key 只保存不可逆哈希。
- 保存用于页面识别的非敏感前缀。
- 不得提供从数据库恢复下游 Key 明文的能力。

### 16.4 业务数据

第一轮至少需要持久化以下数据：

- 管理员账号和密码哈希。
- 管理员会话。
- NVIDIA Key 密文和状态。
- Key 与模型不可用关系。
- 下游访问 Key 哈希和元数据。
- 全局模型白名单。
- 队列和超时配置。
- 请求元数据。
- 最近错误元数据。
- 按日聚合统计。

## 17. 日志、隐私与数据保留

### 17.1 禁止保存的内容

- 用户提示词。
- system、user、assistant 和 tool 消息正文。
- 函数工具参数正文。
- 模型输出正文。
- Embedding 输入正文。
- 上传音频。
- 生成音频。
- Audio Transcriptions 文本正文。
- 完整 NVIDIA Key。
- 完整下游访问 Key。
- Authorization Header。
- 管理员 Cookie。

### 17.2 允许记录的元数据

- 请求 ID。
- 接口类型。
- 模型 ID。
- 下游访问 Key 前缀或内部 ID。
- NVIDIA Key 的内部 ID 或掩码标识。
- HTTP 状态。
- 请求耗时。
- 排队时长。
- 尝试次数。
- 错误分类。
- token 用量。
- 创建时间。

### 17.3 保留期限

- 请求元数据保留 30 天。
- 错误明细保留 30 天。
- 系统定时清理过期明细。
- 不含正文的按日聚合数据可长期保留。

## 18. 备份与恢复

### 18.1 数据库备份

- 提供容器内 CLI 备份命令。
- 使用 SQLite Backup API 生成一致性快照。
- 不允许依赖在线直接复制 WAL 数据库文件作为正式备份方案。
- 管理页面不提供数据库下载。

### 18.2 主密钥备份

- 数据库备份不包含主加密密钥。
- 主加密密钥由使用者在容器和数据库之外单独备份。
- 恢复时必须同时具备数据库备份和原主密钥。
- 缺少原主密钥时，不承诺恢复 NVIDIA Key。

## 19. 健康检查与运行状态

### 19.1 存活检查

```http
GET /health/live
```

用于判断进程是否存活，只返回最小状态，不返回 Key、模型或统计信息。

### 19.2 就绪检查

```http
GET /health/ready
```

用于判断服务是否具备接收请求的基本条件。至少应考虑：

- 数据库是否可用。
- 数据库迁移是否完成。
- 主加密密钥是否可用。
- 管理员是否完成首次改密。
- 服务是否处于关闭流程。

详细 Key 池信息只能在登录后的管理页面查看。

## 20. 部署要求

### 20.1 目标环境

- 单台 Linux 服务器。
- 固定公网 IP。
- TCP 80 和 443 可开放，但第一轮不使用证书设计。
- Docker Compose。
- 单应用实例。
- SQLite 数据目录使用持久化卷。

### 20.2 网络方式

- 第一轮 API 和管理页面通过普通公网 HTTP 暴露。
- 第一轮不包含 HTTPS、证书和反向代理配置。
- 应用不得假装当前部署具备链路加密。

### 20.3 已接受风险

公网 HTTP 会明文传输：

- 管理员用户名和密码。
- 管理员会话 Cookie。
- 下游访问 Key。
- API 请求和响应内容。

该风险属于已确认的第一轮限制。部署文档必须醒目标注，不得将第一轮公网 HTTP 部署描述为安全生产方案。

### 20.4 优雅关闭

- 第一轮允许升级时短暂停机。
- 收到关闭信号后停止接收新请求。
- 停止接受新的队列请求。
- 在限定宽限期内等待现有请求结束。
- 宽限期结束后取消剩余上游请求。
- 最后关闭数据库和进程。
- 不设计双实例无损升级。

## 23. 验收标准

### 23.1 API 验收

- OpenAI SDK 可以通过下游访问 Key 调用本服务。
- `/v1/models` 只返回启用的全局白名单模型。
- Chat Completions 普通和流式请求均可完成。
- Responses 普通和流式请求均可完成支持范围内的转换。
- Embedding 和 Audio 接口在 NVIDIA 实际支持时可调用。
- 未支持接口不会被透明转发。

### 23.2 调度验收

- 健康 Key 按限流感知 Round Robin 选择。
- 单 Key 同时最多执行 1 个请求。
- 忙碌、冷却、停用和模型不可用 Key 会被跳过。
- 首字节前的可恢复错误会切换 Key。
- 同一个请求不会重复尝试同一个 Key。
- 已输出首字节后不会重放请求。
- 遍历过程受统一总超时预算约束。

### 23.3 管理验收

- 首次登录必须修改 `admin/admin`。
- 改密前代理 API 和敏感管理功能不可用。
- 能单个和批量添加 NVIDIA Key。
- 批量导入能返回逐行结果并接受部分成功。
- 能启停、删除和手动测试 NVIDIA Key。
- 能创建和撤销多个下游访问 Key。
- 下游 Key 明文只展示一次。
- 能维护模型白名单。
- 能查看 Key 池、队列、最近错误和基础统计。

### 23.4 数据与安全验收

- SQLite 不保存 NVIDIA Key 明文。
- SQLite 不保存下游访问 Key 明文。
- 错误主密钥会导致服务拒绝启动。
- 日志不包含 Authorization、Cookie 或完整 Key。
- 请求和响应正文不写入数据库或日志。
- 请求明细和错误记录能按 30 天规则清理。
- CLI 能生成一致性数据库备份。
- CLI 能重置管理员密码并撤销会话。

### 23.5 部署验收

- Docker Compose 能在单台 Linux 服务器启动。
- SQLite 数据和配置在容器重建后保留。
- `/health/live` 和 `/health/ready` 可供 Docker 健康检查使用。
- 服务支持优雅关闭。
- 部署文档明确标注公网 HTTP 风险。

## 26. 需求结论

第一轮产品是一个面向个人使用的 NVIDIA Build API 专用路由器。它以安全管理多个 NVIDIA Key、限流感知轮询、首字节前故障转移、OpenAI-compatible 接口和可操作的 Web 运维面板为核心。

第一轮优先保证代理协议、Key 调度、SSE、数据安全和单机部署正确，不为未来团队化或多厂商能力提前引入复杂平台架构。所有延期项必须在后续需求确认后再进入设计和实现。

# 第三轮优化说明：代理质量与管理端交互

更新日期：2026-08-12

## 目标

本轮按四个方向持续迭代：① 模型反代稳定性；② 代理 IP 选择质量（避免劣质 IP）；③ UI 与交互（对齐 `设计美学研究` 约束）；④ 审查与同类项目参考中的其他高价值项。

## 一、后端：代理 IP 质量（方向 ②）

### 1. HTTP 层失败感知，劣质 IP 真正可被剔除

- **问题**：此前 `client.go` 对任何响应（含 429/5xx）都走 `ReportLatency`，代理池把"被上游限流的 IP"当成健康且最快，甚至清除他人隔离状态。一个被 NVIDIA 限流/封禁的出口永远留在池顶。
- **修复**（`internal/upstream/nvidia/client.go`、`internal/xkproxy/pool.go`）：
  - 仅 2xx 上报成功（清隔离、更新 EWMA）；
  - 429/5xx 走新增 `ReportHTTPFailure`：连续达阈值（默认 6）后隔离，重复隔离超上限则永久移除（5 分钟冷却）；
  - **多数派门控**：只有当池内某个出口近期真正服务过 2xx 时才允许因 HTTP 失败隔离出口——key 级/全局限流（如共享配额 429 风暴）不会把整池误伤清空；
  - HTTP 失败不喂 EWMA（快速拒绝不得让失败出口"看起来最快"）；真实 2xx 重置计数。
- **落点**：`http_fail_count` 暴露到代理池状态接口，管理端可看到限流信号。

### 2. 池空可重试，不再硬失败

- **问题**：池空（TTL 全部过期、上游采集失败）时请求直接 502 且不可重试。
- **修复**（`internal/xkproxy/manager.go`、`internal/router/attempt.go`）：池空返回 `ReasonNoHealthyProxy`，router 转为**可重试 503** 并跨 key 重试（带退避），且不冷却 key（请求从未到达上游）。

### 3. 会话粘性周期重选

- **问题**：每个 NVIDIA key 的出口经 transport 缓存钉死，key 若被钉在"变慢但不出连接错误"的 IP 上会一直受影响。
- **修复**（`internal/xkproxy/manager.go`）：缓存条目超过 60s 且池内有更优出口时重建 transport（池内最佳仍是当前出口则跳过，避免空转重连）。

### 4. 上游采集失败退避 + TTL 宽限

- **退避**（`collector.go`）：连续失败指数拉长采集间隔（最高 8×），限流/账号码不再固定间隔硬拉。
- **TTL 宽限**（`pool.Grace`）：上游 XApi 短时不可用时，对 live 代理延长过期时间（默认每次 +60s，2×TTL 封顶），保留 last-known-good 出口；过期代理仍正常淘汰。

## 二、后端：模型反代稳定性（方向 ①）

- 与代理质量改动共同改善：HTTP 失败隔离、池空重试、会话重选、上游退避与宽限，均直接作用于"请求能否稳定走通、出口是否健康"。
- 复核确认两项审计项无需改动：`nonstream_total_timeout_ms` 数据库默认 300000ms（5 分钟），非报告所述 1s；登录限流已通过 `TrustedProxies` + `ClientIP` 解析真实客户端 IP，非按 RemoteAddr 共享桶。

## 三、前端：UI 与交互（方向 ③，对齐设计美学约束）

- **全局 toast 反馈系统**（`web/src/shared/toast.ts` + `ToastHost.vue`）：成功/错误/信息/警告，自动消失 + 手动关闭，`aria-live` 播报，深色面板 + 内联 SVG 图标（不用 emoji），动画遵守 `prefers-reduced-motion`。
- **操作反馈不再静默**：NVIDIA Key 启停/删除、Access Key 撤销、模型启停/单价/解 block、提供商创建/启停均给出 toast。
- **错误位置修复**：NVIDIA Key 页列表操作错误不再渲染进"单个导入"卡片；批量测活空结果给出明确提示。
- **确认弹窗统一**：Access Key 撤销由 `window.confirm` 改为两段式按钮确认（与 NVIDIA Key 一致）。
- **代理池页**：上次更新时间、`http_fail_count` 限流信号徽章、空态文案区分（静态模式/隔离冷却）。
- **Live 页**：真正的自动滚动（钉顶才滚动）+ 回到最新按钮 + 清空。
- **审计页**：`input` class 笔误修复、窄屏横向滚动、翻页加载态、详情 hover 查看。
- **运行状态页**：摘要每 5 秒轮询 + 更新时间。
- **监控页**：趋势每 30 秒自动刷新（不打扰日志分页）+ 更新时间；修复潜伏 bug——Vue 对 `type=number` 输入自动转数字，原筛选解析的 `value.trim()` 遇数字会抛错；无效筛选现在内联提示且不触发重载。
- **提供商页**：加载 spinner、刷新按钮、创建/启停 toast、Base URL 格式校验。
- **模型页**：保存白名单后候选勾选与已配置集合再同步。

## 五、未做项与理由

- **单代理手动重检端点**：上游每 5s 重采集校验，手动重检最多省 5s 等待，收益小于 API 面增量，暂不做。
- **`NVIDIA_ROUTER_XK_EXPECTED_QTY` 默认值调整**：该配置在当前代码中是死配置（存储但未参与请求构造），改默认值无实际效果，需先接线上游数量参数（上游契约未验证），留待联调时确认。
- **MaxLatency 默认值**：无真实延迟测量依据，设硬默认可能误伤国内慢出口，保持关闭并在池状态页展示实测延迟供运维参考。
- **Provider "测试连接"**：第三方提供商的服务链路尚未装配（凭据仅入库），重建客户端做探活属投机性工作。
- **race 检测**：本机无 CGO 工具链，`go test -race` 不可用；并发路径沿用现有锁结构并有既有并发测试覆盖。

## 1. 实现范围

- `internal/xkproxy`：Fetcher（5s 超时、4 KiB 限制、安全 `IP:PORT` 解析、禁用进程代理）与 Manager（租约状态机、并发懒提取合并、1 秒负缓存、按超时组合缓存 Transport、错误退役、幂等 Close）。
- `internal/upstream/nvidia`：共享 `do()` 发送器，全部端点（Models/Chat/Embeddings/ASR/TTS）经代理；`WroteRequest` 写前故障退役+同 Key 重放一次；`releaseBody` 幂等释放；响应 Body 关闭不清池。
- `internal/config`：三个 `NVIDIA_ROUTER_XK_PROXY_*` 变量校验（qty=1、TTL 30s~30min、renew<ttl、错误脱敏）。
- `internal/app`：Manager 注入/关闭、nil Transport 回退默认、非 `*http.Transport` 启动安全失败。
- `internal/nvidiakey` / `modelcatalog` / `router` / admin：`ValidationProxyUnavailable` 状态、代理错误不污染 Key 状态、502 `upstream_proxy_unavailable`。
- `tests/mocknvidia`：端到端代理 fixture（fetch API + CONNECT 代理 + TLS 上游），全端点覆盖、无直连回退、同 Key 重放恰一次、密钥泄漏门禁。
- `scripts/test/live-xkproxy.sh` 与 `docs/星空代理真实联调说明.md`。

## 2. 过程中发现并修复的问题

1. **代理模式流式请求 499 bug**：`doProxyAttempt` 的 `context.WithDeadline(FirstByteDeadline)` 在 `Do` 返回后立即 cancel，杀死 SSE/音频 body 读取。修复：request context 不再包 deadline（首字节由 Transport `ResponseHeaderTimeout` 承担），用 `GotFirstResponseByte` + 独立 watch 维护首字节语义。mocknvidia `TestProxyStreamingRequests` 已改为断言 200。
2. **`.dockerignore` 的 `**/audio` 误排除 `internal/protocol/audio` 源码目录**，导致容器镜像构建失败。已删除该规则（音频文件已由 `**/*.wav`/`**/*.mp3` 等覆盖）。
3. **基线 lint 欠债**：全仓库 golangci-lint 46 项告警（errcheck 34、ineffassign 2、staticcheck 5、unused 5）清零，`golangci-lint run ./...` 本地 0 issues。
4. **shutdown 测试端口 TOCTOU**：`TestAppCloseClosesDatabaseAfterHTTPGraceTimeout` 先探测端口再关闭重绑，CI 并行下端口被抢导致 5s 超时稳定失败。新增 `Server.ServeOn(listener)` 支持外部 listener 注入，测试不再重绑定端口。

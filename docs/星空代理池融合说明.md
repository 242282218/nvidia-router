# 星空代理池融合说明

## 概述

星空代理池项目已完全融合到 nvida反代 项目的 `internal/xkproxy` 模块中,提供内置的代理池管理能力。

## 架构变化

### 融合前
```
nvida反代 → 外部星空代理池服务 (HTTP正向代理) → NVIDIA API
```

### 融合后
```
nvida反代 (内置代理池) → 动态代理IP → NVIDIA API
```

## 核心模块

### 1. model.go - 代理模型
- `Proxy` 结构体:代理的完整生命周期数据
- 支持 HTTP/HTTPS 代理协议
- TTL 管理、健康检查、隔离策略

### 2. pool.go - 代理池
- 并发安全的代理池管理
- 轮换选择策略(最新优先)
- 失败隔离与自动恢复
- 会话粘滞(Sticky Session)支持
- 延迟感知选择(慢速代理降级)

### 3. upstream.go - 上游采集
- 星空代理 API 对接
- TXT 格式解析
- 错误码识别(204/205/403/406等)
- 限流与账户级错误处理

### 4. validator.go - 代理验证
- 通过验证 URL 测试代理可用性
- 延迟测量(用于选择优化)
- 连接复用(减少验证开销)

### 5. collector.go - 采集调度器
- 定时采集(默认 5 秒间隔)
- 并发验证(可配置并发数)
- 自动合并到代理池
- 错误回退策略

### 6. manager.go - 管理器(扩展)
- 兼容原有外部 HTTP 代理模式
- 新增内置代理池模式
- 传输层缓存与会话隔离

## 使用方式

### 模式一:外部 HTTP 代理(原有模式,保持兼容)

```go
manager, err := xkproxy.New(proxyURL, authKey, baseTransport, logger)
```

配置环境变量:
```bash
NVIDIA_ROUTER_XK_PROXY_URL=http://proxy-pool:8080
NVIDIA_ROUTER_XK_PROXY_AUTH_KEY=your-auth-key
```

### 模式二:内置代理池(新模式)

```go
cfg := xkproxy.CollectorConfig{
    UpstreamURL:       "https://api.xingkongdaili.com/...",
    UpstreamTimeout:   4 * time.Second,
    ValidationURL:     "https://integrate.api.nvidia.com/v1",
    ValidationStatus:  404,
    ValidationTimeout: 5 * time.Second,
    Interval:          5 * time.Second,
    ProxyTTL:          120 * time.Second,
    ExpectedQty:       2,
    Concurrency:       2,
    EjectionPolicy: xkproxy.EjectionPolicy{
        FailureLimit: 3,
        BaseDuration: 10 * time.Second,
        MaxDuration:  60 * time.Second,
        MaxEjections: 3,
    },
}

manager, err := xkproxy.NewWithPool(cfg, authKey, baseTransport, logger)
manager.StartCollector(ctx)
```

配置环境变量(内置池模式已接入生产配置链路):
```bash
NVIDIA_ROUTER_XK_UPSTREAM_URL=https://api.xingkongdaili.com/api/getproxy/...
NVIDIA_ROUTER_XK_VALIDATION_URL=https://integrate.api.nvidia.com/v1
NVIDIA_ROUTER_XK_VALIDATION_STATUS=404
NVIDIA_ROUTER_XK_PROXY_TTL=120s
NVIDIA_ROUTER_XK_COLLECT_INTERVAL=5s
NVIDIA_ROUTER_XK_CONCURRENCY=2
# 可选:拒绝验证往返超过该阈值的慢代理(避免池整体退化到最慢出口)
NVIDIA_ROUTER_XK_MAX_LATENCY=2s
```

**注意**: `NVIDIA_ROUTER_XK_UPSTREAM_URL` 与 `NVIDIA_ROUTER_XK_PROXY_URL`(静态代理)互斥,不能同时配置。内置池模式下,`NVIDIA_ROUTER_XK_AUTH_KEY` 认证的是星空 API,不是固定代理。

### 管理界面状态

启用内置池后,管理端「代理池」页会实时显示:
- 健康代理数 / 总代理数
- 每个出口的地址、EWMA 延迟、剩余 TTL、健康/隔离状态、成功/失败计数

状态数据来自 `GET /admin/api/proxy-pool/status`,每 10 秒自动刷新。

## 关键特性

### 1. TTL 淘汰
- 代理过期立即剔除
- 本地 TTL 默认 120 秒(给上游 3 分钟时效预留传输时间)

### 2. 失败隔离
- 连续失败达阈值后短暂隔离(不删除)
- 隔离窗口递增(10s → 20s → 30s,最大 60s)
- 成功后逐步恢复,最多隔离 3 次后删除

### 3. Panic 模式
- 所有代理被隔离时,忽略隔离状态继续使用
- 保证可用性优先

### 4. 会话粘滞
- 同一会话(X-XK-Session 或客户端 IP)绑定同一出口
- 避免 AI 供应商按源 IP 风控

### 5. 延迟优化
- 记录每个代理的验证延迟 EWMA
- 慢速代理(>3倍最快)自动降级到候选列表末尾

### 6. 上游错误处理
- 限流错误(403/406):退避 30 秒
- 账户错误(204/205/208/211/302/430/432):冷却 5 分钟
- 传输错误:冷却 10 秒

## 监控指标

通过 `manager.PoolStatus()` 获取:
```go
type PoolStatus struct {
    TotalSize   int      // 总代理数(含隔离)
    HealthySize int      // 健康代理数(可用)
    Proxies     []Proxy  // 代理详情列表
}
```

每个 `Proxy` 包含:
- `Address`: IP:PORT
- `FetchedAt`: 采集时间
- `ValidatedAt`: 验证时间
- `ExpiresAt`: 过期时间
- `HealthFails`: 连续失败次数
- `EjectedUntil`: 隔离解除时间
- `LatencyEWMA`: 平滑延迟(毫秒)
- `SuccessCount` / `FailureCount`: 累计成功/失败次数

## 日志事件

- `upstream_fetch_start` / `upstream_fetch_success` / `upstream_fetch_failed`
- `proxy_validation_failed`(debug 级别)
- `pool_updated`
- `proxy_transport_retired`

## 配置建议

### 生产环境
```bash
NVIDIA_ROUTER_XK_UPSTREAM_URL=<星空 API 完整 URL>
NVIDIA_ROUTER_XK_VALIDATION_URL=https://integrate.api.nvidia.com/v1
NVIDIA_ROUTER_XK_VALIDATION_STATUS=404
NVIDIA_ROUTER_XK_PROXY_TTL=120s       # 给传输预留 60s
NVIDIA_ROUTER_XK_COLLECT_INTERVAL=5s  # 星空推荐频率
NVIDIA_ROUTER_XK_CONCURRENCY=2        # 与每次获取数量一致
```

### 开发/测试
```bash
# 使用外部代理池(更简单)
NVIDIA_ROUTER_XK_PROXY_URL=http://127.0.0.1:8080
NVIDIA_ROUTER_XK_PROXY_AUTH_KEY=your-key
```

## 迁移指南

### 从外部星空代理池迁移到内置池

1. **停止外部星空代理池服务**
2. **更新环境变量**:
   - 移除 `NVIDIA_ROUTER_XK_PROXY_URL`
   - 移除 `NVIDIA_ROUTER_XK_PROXY_AUTH_KEY`
   - 添加 `NVIDIA_ROUTER_XK_UPSTREAM_URL`(星空 API 直接地址)
   - 添加 `NVIDIA_ROUTER_XK_VALIDATION_URL` 和相关配置
3. **重启服务**
4. **监控日志**:确认 `upstream_fetch_success` 和 `pool_updated` 事件

### 优势
- 减少一层网络跳转(延迟更低)
- 无需独立部署代理池服务
- 统一监控和日志
- 更精细的失败处理和健康检查

### 注意事项
- 内置池模式需要服务直接访问星空 API
- 确保服务出口 IP 在星空白名单中
- 多实例部署时,每个实例独立采集(不共享池)

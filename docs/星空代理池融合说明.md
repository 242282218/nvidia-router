# 星空代理池融合与运行边界

## 结论

本项目已经吸收 `D:\PROJECT_ZZZZZZZZZ\星空代理池` 中的代理生命周期、TXT 解析、TTL、失败隔离、连接复用、粘滞会话、质量评分和 HTTP CONNECT 设计，统一位于 `internal/xkproxy`。

生产运行边界遵循项目安全约定：

```text
nvida反代（内置采集器/代理池/CONNECT） ──动态出口──> NVIDIA
```

`nvida反代` 直接请求 XApi、解析并验证出口。XApi 完整地址可保留在运行时内存，也可由管理员页面提交后使用主密钥加密保存；它不会出现在日志或 API 响应中。没有任何 XApi 配置时，已启用的内置池拒绝启动；池未就绪时不会静默直连 NVIDIA。

## 已吸收的代理逻辑

- `Proxy` 生命周期：采集时间、验证时间、TTL、过期淘汰。
- TXT 兼容解析：CRLF/LF、空行、重复项、`host:port`、带认证格式和 URL 格式。
- 上游错误识别：区分 provider code、传输错误和解析错误；敏感 URL 不进入日志。
- 代理质量：验证延迟 EWMA、真实 NVIDIA 请求成功/失败、请求首字节延迟和质量分。
- 故障处理：传输失败计数、限时隔离、指数隔离窗口、重复失败移除和冷却后重新接纳。
- 选择策略：轮换、慢出口降级、粘滞会话、连接缓存和过期前 CONNECT 保护。
- 安全边界：Proxy-Authorization、管理鉴权、目标地址保护、并发上限、请求体限制、无直连回退。
- 监控：代理池页展示外部池连通性与健康探测延迟；单个出口明细留在代理池控制台。

## 推荐部署

只部署 `nvida反代` 单体服务。国内出口环境通过运行时 Secret 注入：

1. 启动 `星空代理池`，由它读取 `UPSTREAM_API_URL`、`PROXY_AUTH_KEY` 和 `ADMIN_AUTH_KEY`。
2. 确认代理池 `GET /healthz` 为 200、`GET /readyz` 在管理员 Key 下为 200。
3. 启动 `nvida反代`，设置：

```dotenv
NVIDIA_ROUTER_XK_UPSTREAM_URL=<由 Secret Provider 注入的完整 XApi 地址>
NVIDIA_ROUTER_XK_VALIDATION_URL=https://integrate.api.nvidia.com/v1
NVIDIA_ROUTER_XK_VALIDATION_STATUS=404
```

启动后在 NVIDIA Router 管理页“代理池”确认采集状态和有效出口数量。业务请求只能经过内置池；池未就绪不得直连。

## 管理页交互

`/admin/api/proxy-pool/status` 返回安全投影：

- `mode=built-in`
- `configured`
- `healthy_size` / `total_size`
- 最近采集时间和上游错误分类
- 脱敏后的 XApi endpoint（不含 query）

Web 不展示 XApi query 凭据；代理出口地址只用于池内质量表和运维排查。

页面包含加载、空、错误、过期数据提示；状态轮询失败时保留最近成功数据并明确标记，不把旧数据当作实时数据。

## 测试

无秘密静态检查：

```bash
bash -n scripts/test/live-xk-proxy.sh
NVIDIA_ROUTER_XK_PROXY_LIVE_SELF_TEST=1 bash scripts/test/live-nvidia.sh
```

工作场景联调脚本从 `key/key.txt` 读取第一条非空 NVIDIA Key，但不会打印 Key；运行前仍必须注入管理员密码、路由器地址、模型名和临时代理认证 Key：

```bash
export NVIDIA_ROUTER_LIVE_BASE_URL='http://127.0.0.1:3756'
export NVIDIA_ROUTER_ADMIN_PASSWORD='<runtime-only-admin-password>'
export NVIDIA_ROUTER_LIVE_CHAT_MODEL='<enabled-chat-model>'
export NVIDIA_ROUTER_LIVE_EMBEDDING_MODEL='<enabled-embedding-model>'
export NVIDIA_ROUTER_XK_UPSTREAM_URL='<runtime-only full XApi URL>'
bash scripts/test/live-xk-proxy.sh
```

脚本会先检查 `mode=built-in` 且采集器已启用，再执行现有 NVIDIA 主路径测试，并执行既有临时凭证清理。没有逐项 `status=PASS` 证据时，不得宣称真实联调通过。

> `key/key.txt` 中的 Key 一旦曾经进入聊天、日志或其他非受控位置，应立即在 NVIDIA 侧全部轮换；本项目不把它们复制到源码或环境示例中。
